# Advanced по подпискам — спецификация к макету 2026-11-01

**Статус: основной вид принят владельцем 2026-11-01** («нравится вариант "короткие имена"»). Переключатель стоит справа от заголовка. Цена `$200/мес` — в столбце «ПО ПОДПИСКЕ». Строка «в активный день» — с полными именами подписок.

Макет: `design/mockups/advanced-subscriptions-2026-11-01.html` — самодостаточный HTML, 1 CSS px = 1 pt, есть переключатель масштаба 1×/2×. Эталон: `docs/advanced.png` (3.1.4). Все размеры в pt, ось Y идёт вниз от верха панели, как в `rectTL`. Рядом с константой, которая уже есть в коде, стоит ссылка `файл:строка`; без ссылки — новое значение.

**Модель данных (решение владельца 2026-11-01).** У каждого продукта не больше одной подписки; она может работать на VPS и на нескольких компьютерах. Поэтому в «Истории и деньгах» 1–2 закладки (Claude и/или Codex) и столько же строк таблицы. Расход складывается со всех машин; машины не упоминаются ни в закладках, ни в таблице, ни в подписях. Групп «не указан» нет. Имя подписки — пользовательская `L` (до 32 знаков), иначе `<Продукт> <план>`: `Claude Max`, `Codex Pro`.

Шрифт системный (SF Pro). Цвета: `textHi` белый 0,95 · `textMid` 0,5 · `textLo` 0,34 (`LimitsMonitor.swift:5854`); `ADV_*` — `LimitsMonitor.swift:5560–5568`. Капс `caps()` — semibold, межбуквенный интервал 0,06·size (`LimitsMonitor.swift:5864`).

## 1. Карточки лимитов: без пустого низа

- Высота карточки — как в эталоне: `38 + Σ строк + (n−1)`. Футер добавляет **0 pt**, если в нём нет строки состояния 2–7. Сейчас `AdvCard.height` всегда прибавляет `remoteQuotaFooterHeight(advanced: true) = 18` (`LimitsMonitor.swift:5688`, `RemoteLimitsC3B.swift:115`) — отсюда пустое место. Нужно прибавлять 18 только при непустом `statusLine` (UX §4, состояния 2–7). Строка источника не рисуется и места не занимает.
- Проверка по макету: Claude (3 полные строки) = 38 + 186 + 2 = **226**. Codex (неделя 62 + сессия 50 + сбросы 24) = 38 + 136 + 2 = **176**.
- Заголовок карточки без пользовательской подписи — как в коде (`RemoteLimits.swift:1359–1360`): `Claude Code` / `Codex`, 13 semibold; плашка плана 9.5 semibold (h 16, отступ по бокам 7, белый 0,09); затем точки свежести `· ● vps` 11 regular `textMid`: точка 6 pt, 3 pt до имени (`drawRemoteSourceHeader`, `LimitsMonitor.swift:5004`). Иконка 16 pt в (26, y+10), стрелка 12 pt в (322, y+12).

## 2. Переключатель «История и деньги»

- Заголовок: шеврон 8×9 в (26, hy+4.5); `ИСТОРИЯ И ДЕНЬГИ` — caps 9.5 `textLo`, x 40, h 18; `hy = y + 8`. Приписки `· N ПК` нет.
- Вид как в эталоне: контейнер h 18, радиус 9, белый 0,07, внутренний отступ 2. Сегменты h 14, ширина = текст + 16, между сегментами 1. Выбранный: заливка 0,18, радиус 7, 10.5 semibold `textHi`; остальные: 10.5 medium `textMid`. Подпись сегмента — имя подписки.
- **Место — одно правило, без переноса во вторую строку:**
  1. **Справа от заголовка**, если `Σ(текст+16) + (n−1) + 4 + ширина заголовка + 22 ≤ 308`. Правый край — 334, top = hy, к высоте +0. Это принятый основной вид (`Claude Max | Codex Pro`) и случай одной подписки (фрагмент 1 макета).
  2. **Иначе — своей строкой на всю ширину**: контейнер (26, hy+22, 308, 18), карточка выше на **+22**. Две закладки делят 304 − 1 pt поровну. Если одна подпись не влезает в половину, а сумма влезает — каждая берёт свою ширину плюс половину остатка. Если не влезает и сумма — короткая закладка сохраняет свою ширину, длинная получает остаток, её подпись **обрезается многоточием в конце**. Полная `L` — в подсказке и AX. Шрифт не уменьшать: убрать `size = min(10.5, …)` (`LimitsMonitor.swift:6177`). Пример — фрагмент 2 макета.
- В `remoteHistorySelectorLayout` (`RemoteLimitsC3B.swift:360`) убрать перенос по строкам (`row += 1`) и условие `titles.count >= 3`.

## 4. Таблица денег — одна строка на подписку

`my = by + 82`. Разделитель 1 pt, белый 0,06, на `my+4`, x 26…334.

| Элемент | Значение |
|---|---|
| Заголовки (caps 8.5 `textLo`, top `my+10`, h 11), **выравнивание вправо** | `ПО ПОДПИСКЕ` → правый край **190** (`ADV_IX+164`) · `ПО API БЫЛО БЫ` → **283** (`ADV_IX+257`) · `ВЫГОДА` → **334** (`ADV_IX+ADV_IW`) |
| Строка i | top `my + 23 + 15·i`, h 13, шаг **15**, как в 3.1.4 (сейчас 38, `LimitsMonitor.swift:6333`) |
| Имя | x 26, 10.5 semibold `textHi`, ширина ≤ `190 − ширина(цена) − 8 − 26` (≈ 108 pt). Не влезает — многоточие в конце; полное `L · $200/мес` — в подсказке. Шрифт не уменьшать: убрать `labelSize` (`LimitsMonitor.swift:6319`) |
| ПО ПОДПИСКЕ | `$200/мес`, 10.5 regular `textHi`, правый край 190. Оценочная цена: `≈$200/мес`, карандаш 10×10 `ADV_LINK` слева с зазором 3 pt (нажатие → Настройки) |
| ПО API БЫЛО БЫ | `≈ $200/день`, 10.5 regular `textHi`, правый край 283; нет расхода — `пока нет`, `textLo` |
| ВЫГОДА | `×30,0`, 10.5 regular `textHi`, правый край 334; формат `remoteMoneyValue` (`LimitsMonitor.swift:1305`) |

Вместо `colX = [26, 116, 203, 334]` с выравниванием влево (`LimitsMonitor.swift:6307`) — три правых края: 190, 283, 334. Деньги — `remoteMoneyDaily`: от $10 целыми, меньше — с центами. Сумма по подписке за день (`≈ $6,67/день`) в таблице не выводится; выгода считается как раньше.

## 5. Строка «в активный день по API»

- x 26, 9.5 regular `textLo`; top `my + 23 + 15·n + 2`; h 11; шаг строк 12; ширина 308.
- Порядок ужатия (без многоточия):
  1. Полные имена: `в активный день по API: Claude Max ≈ $350 · Codex Pro ≈ $190`. Принятый вид, помещается.
  2. Если полная строка шире 308 pt (длинные `L`) — имена продуктов `Claude` / `Codex`. Путаницы нет: подписка у продукта одна.
  3. Если и так шире — перенос между пунктами по ` · `, пункт целиком уходит на новую строку.
- Высота считается той же функцией: `remoteMoneyNoteLines` (`RemoteLimits.swift:964`) и `remoteHistoryMoneyExtraHeight` (`RemoteLimits.swift:955`), пересчитать под шаг 15 и эти правила.

## 6. Высоты

- Развёрнутая карточка истории: `8 + 22 + extra + 82 + 23 + 15·n + 2 + 12·lines − 1 + 9`. Принятый вид (n 2, extra 0, 1 строка) = **187** — ровно `ADV_HIST_EXPANDED`, как в эталоне. Одна подписка = **172**.
- Окно: `58 + Σ(карточка + 5) + история + 6 + 59` (`LimitsMonitor.swift:5785`). Макет: 58 + 231 + 181 + 187 + 65 = **722 pt**.
- **Окно обязано вырасти под эту высоту вместе с футером** — дефект 5 со снимка. Высоту окна и отрисовку считает одна функция. Если панель выше экрана — прокрутка `mainScroll`, футер не обрезается.
