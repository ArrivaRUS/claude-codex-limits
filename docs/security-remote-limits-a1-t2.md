## 3. Новые находки

### N1 — major (Opus + Astra) · одиночный суррогат в чужом файле роняет каждый цикл синхронизации
`sync.py:388–391` (`_machine_text` отсекает только `Cc`/`Cf`, а у одиночного суррогата категория `Cs`), `:435` (`tz` без проверки), `:444–454` (ключи `p`/`d`/`model` старого пути `days` без проверки) → `:813` `common.write_json(SYNC_REMOTE_PATH, remote)` → `common.py:89–94/65–66`: `ensure_ascii=False` + `.encode("utf-8")` → необработанный `UnicodeEncodeError`.
- **Вектор:** писатель с токеном кладёт `machine-evil.json`, в котором стоят шесть ASCII-символов `\ud800` в `machine.name`, `os`, `app`, `tz` или в ключе дня/модели корневых `days`. Байты ASCII-корректны, а `json.loads` превращает их в одиночный суррогат.
- **Воспроизведение (сделано офлайн):** `sync.merge` → `write_json` падает для name/tz/day/model; полный `sync.sync_cycle` (обвязка `TestA114ReaderLimits.cycle_with`) на `{"machine-evil.json": <name="\ud800">, "machine-good.json": …}` бросает `UnicodeEncodeError`.
- **Последствия:** `lastOkAt` не двигается, кеш машин не обновляется. `ccl-sync push --auto` под таймером падает с трейсбеком на каждом проходе, пока файл лежит в gist, а трей пишет ошибку. Это нарушает C7 «один враждебный файл не останавливает синк» и критерий готовности A1. В порядке v1.1 (GET → merge → решение → PATCH №1) издатель на VPS **вообще перестанет публиковать лимиты**. Новый блок `accounts` защищён: `_text` проверяет кодируемость. Дыра в старых полях и в новой `_machine_text`.
- **Фикс:** один валидатор строк (кодируемость в UTF-8 плюс отсутствие `Cc`/`Cf`, то есть `accounts._text`) для `machine.name/os/app`, `tz` и всех ключей `p`/`d`/`model` в `merge`; плохое поле или запись отбрасывать. Вторым рубежом поймать `UnicodeEncodeError` при записи `sync-remote.json` и выбросить проблемный файл, а не цикл.
- **Тест-на-атаку:** hostile-файлы с `\ud800` (name, os, app, tz, day, model) плюс один нормальный → `res.ok` (или только `lastError` без исключения), нормальная машина слита, `sync-remote.json` записан, `ccl-sync status` не падает.

### N3 — major (Astra) / minor (Opus) → **major** по правилу «строже» · редирект на raw-пути обходит предел тела
`common.py:441` (`urlopen` с редиректами для GET без авторизации, `sync.py:59–61`) → CPython 3.14.4 `HTTPRedirectHandler.http_error_302`: `fp.read(); fp.close()`. Тело промежуточного 30x читается **без предела** до `read(max_body+1)`, и разрешены переходы на `http`/`ftp`.
- **Вектор:** ответ 302 с бесконечным телом на запрос `raw_url`. Для эксплуатации нужен контроль над ответом raw-хоста или MITM; одним содержимым gist этого не добиться — `raw_url` выдаёт GitHub API (это и есть основание Opus для minor).
- **Фикс:** для `_raw` поставить свой redirect-обработчик: тело не дренировать, только https, хост из allow-list `gist.githubusercontent.com`, ≤ 3 перехода. Либо `follow_redirects=False`, если raw-URL с sha не редиректит (проверить в P21½). Плюс общий дедлайн чтения (например, 60 с на raw), потому что `timeout=30` ограничивает только одну операцию сокета.
- **Тест:** подставной opener: 302 с телом из потока без конца → прочитано ≤ cap+1 байт, переход на `http://` или чужой хост не выполнен.

### N2 — minor (Opus + Astra) · ESC-последовательности из gist доходят до терминала
`cli.py:268–284`: живой `ccl-sync status` разбирает `gist.files[*].content` сам, минуя `_machine_text`, и печатает `name/os/app` как есть (`:292–295`). Второй путь — `cli.py:344` `dump --merged`: ключ модели из чужих `days` (`sync.py:444–454` не чистит). Вход `"name":"\u001b[2Jspoof"` печатает настоящий ESC (подтверждено Astra синтетически, Opus — чтением). Одиночный суррогат здесь же роняет `print` (`UnicodeEncodeError`).
- **Фикс:** живой `status` строит список через тот же валидатор (или через `sync.merge`); ключи `days` проверять в `merge` (см. N1).
- **Тест:** вывод `cmd_status` и `cmd_dump --merged` на hostile-фикстуре: нет `\x1b`, `‮`, исключения нет. Т30 и критерий готовности A1 («…и `status`») этого требуют.

### N4 — minor (Astra, подтверждено) · бюджет 64 МиБ проверяется после чтения
`sync.py:766–805`: девять truncated-файлов по 7,5 МиБ дают 67,5 МиБ прочитанного при 60 МиБ сохранённого; перебор до +8 МиБ+1, ограничен. `test_total_over_64_mib` считает сохранённое.
**Фикс:** `_raw(url, cap=min(MAX_MACHINE_BODY, MAX_TOTAL_BODY-total))`. **Тест** считает байты транспорта.

### N5 — minor (Astra, подтверждено) · `models[].name` у писателя пропускает `@` и `/`
`accounts.py:343–350`: `{"name":"alice@example.org"}` и `"/home/alice/x"` уходят в блок без изменений. В T1 П4-в сказано «та же чистка», протокол требует `@`/`/` только для подписей. Источник имён — бэкенд провайдера, поэтому реальный риск низкий.
**Фикс:** отказ до обрезки, как для подписей (и NFKC-проверка `＠`/`／` для обоих полей), либо явная правка протокола. **Тест:** в A1-10 добавить значения в разрешённых полях.

### N6 — minor (Astra, подтверждено чтением) · битый `accountByDay` в локальном индексе останавливает push
`usage.py:80`, `:108–112`, `:241`: `{"accountByDay":{"claude":[]}}` → `AttributeError` в `prune`/`_attribute_day` на каждом `refresh`. Вектор — тот же UID или повреждение диска; из gist не достижимо.
**Фикс:** при загрузке проверять вложенные dict и строковые значения, битое отбрасывать в «не указан».

### N7 — minor (Opus + Astra) · запасной hostname в теге может нести имя владельца
`common.py:311–313`: без `machineName` берётся первая метка hostname. Типовой hostname Ubuntu-десктопа `<user>-<модель>` превращается в `alex-thinkpad-x1`. Имя попадает в gist и в историю ревизий (неудаляемо, П4-б). Хост VPS — дефолт хостера без имени; тег мака — `macbook` (C3).
**Фикс:** запасной тег `linux`, а hostname только по явному согласию; либо вырезать из hostname токены, совпадающие с `getpass.getuser()` и частями GECOS. Вектор `<user>-<model>` добавить в `sanitize-vectors.json`. Для издателя закрывается в A4 обязательным `--name`.

### N8 — minor (Opus) · GET `/gists/{id}` > 16 МиБ роняет весь цикл, а не один файл
`sync.py:99` → `Resp(0,…)` → `_handle` → стоп **до** собственного PATCH. Около 16 inline-файлов по ~1 МБ от держателя токена (или меньше, если GitHub экранирует управляющие символы как `\u00XX` — **гипотеза**) надолго останавливают и чтение, и публикацию всех машин. Правило протокола «предел действует на файл, не на цикл» для inline-файлов невыполнимо. Класс атаки (держатель токена может просто удалить файлы) уже принят, но удаление самовосстанавливается, а такой gist — нет.
**Фикс (A3):** при переполнении брать список файлов с `raw_url` из `GET /gists` (без содержимого) и читать raw по одному с пределами; собственный PATCH не ставить в зависимость от чтения чужих файлов; событие в O1. Либо честно поправить формулировку протокола.

### N9 — minor (Opus) · повторная загрузка отвергнутых и больших raw на каждом цикле
Слишком большой файл перекачивается (8 МиБ+1) каждые 5–10 мин; в худшем случае до 64 МиБ за проход, около 18 ГБ/сутки на издателе. Для мака на мобильном интернете это деньги.
**Фикс (A3/A4):** негативный кеш по `raw_url` (адрес с sha неизменяем) и кеш разобранного по `raw_url`.

### N10 — minor (Opus, протокол; вне A1 → B2/C1) · будущий `asOf` выигрывает группировку у своего свежего показания
Правило «карточку `(product,label)` выигрывает последний `asOf`» вместе с «`asOf` > now+5 мин показывается с возрастом 0» означает, что держатель токена с `asOf=2099` подменяет на экране владельца показания **его собственного** аккаунта поверх локального свежего чтения.
**Фикс:** запись с `asOf` > now+5 мин не может выиграть у записи с корректным `asOf`, а при равенстве в пределах допуска побеждает локальная. **Тест** в C1/B2.

### N11 — minor (Opus, **гипотеза**) · `tokens.account_id` Codex может быть общим для воркспейса ChatGPT Team
Это аналог П1-а: два пользователя одного Team-воркспейса получат одну метку, и показания смешаются. Владельца с Pro это не задевает. **Проверить** на `auth.json` Team-аккаунта (только ключи и формат, не значения); при подтверждении решают PM и архитектор.

### N12 — minor (Opus) · `localId` не проверяется по форме
`accounts.py:63–71`: допускается строка до ~8 МБ и любой Unicode. Индекс раздувается на 45 дней, а `strip/lower` в Python и Swift расходятся на не-ASCII.
**Фикс:** после strip принимать только `^[0-9A-Za-z-]{8,64}$`, иначе `no_account_uuid`.

### Замечания без отдельной находки
- `accounts.build` бросает `ValueError` при сумме > 10¹⁵ (`accounts.py:375–381`). В A1 вызовов `build` в боевом коде нет; из локальных данных это недостижимо при корректном разбиении (каждый день принадлежит одному аккаунту, а `add_usage` ограничивает значение 10¹⁵). **До A3:** вызывающий код ловит ошибку, публикует блок без `accounts[].days` (весь расход — в корень) и пишет событие O1. Нужен тест.
- Чтение файлов входа на каждом `usage.scan`: утечек нет. Наружу уходят только id и причина; тексты исключений не сохраняются; `localId` в индексе 0600, каталог 0700; в выход `build` id не попадает (Opus + Astra, A1-10). `~/.claude.json` на VPS весит 65 КБ — далеко от предела 8 МБ.
- `Bearer` на `raw_url` не уходит (`sync.py:102–104`); при 401 с телом > 16 МиБ ответ получает статус 0, ложного отзыва входа нет; gzip не распаковывается; лимит CPython в 4300 цифр ловится как `ValueError`.
- В GUI имена чужих машин попадают в `QLabel` с `AutoText` (`gui/app.py:250`, `:656`). Это существовало и раньше, длина теперь ≤ 16; относится к П5-б/Т17 → B2.
- Prompt-injection: в A1 ничего из gist не исполняется и не попадает агентам; данные идут только в отображение. Риск по-прежнему в «агент на VPS с токеном» (T1 §5), он не менялся.
