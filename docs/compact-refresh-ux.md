Цвет обычного статуса/ожидания — прежний читаемый gray `textMid`; действия — прежний `ADV_LINK`. Amber только для ошибки/проблемы доступа, не для refresh, прогресса, успеха или локального cooldown. Не дублировать существующее сообщение ошибки: совпадающую служебную retry/auth-подсказку заменить новым footer; предметную причину и исходное время снимка сохранить в доступных подробностях. Состояние устаревших данных сохраняет прежние визуальные признаки; ошибка запроса не становится доказательством истёкшего входа.

## Состояния и короткие RU / EN подписи

Таблица определяет presentation; источник допуска действий — действующий `QuotaRefreshFeedback` и состояние провайдера. Не менять reducer/scheduler/transport ради текста.

| Состояние | Строка 1 RU / EN | Строка 2 / действие |
|---|---|---|
| Обычный снимок | `Данные 15:43` / `Data 15:43` | Пусто; следующая попытка в tooltip. |
| Нет успешного снимка | `Нет данных` / `No data yet` | Существующая подсказка настройки/входа по реальной причине; не рисовать 0% или выдуманную дату. |
| Запрос идёт | `Обновляем…` / `Refreshing…` | Нет повторного действия; предыдущие значения видны. |
| Свежий успех, включая прежние проценты | `Проверено 15:43` / `Checked 15:43` | Локальное ожидание, если ещё действует; после него пусто. |
| Ошибка сети / fallback | `Не удалось обновить` / `Could not refresh` | `Повторить` / `Retry` только после допуска; иначе локальное/серверное ожидание. Старый снимок и asOf сохраняются. |
| Локальная защита | Сохранять результат последней попытки | `Повтор через 12 с` / `Retry in 12 s`, без активной кнопки. 30 с от начала запроса; обновлять без изменения геометрии. |
| Серверная пауза | `Ожидание сервиса` / `Service wait` | `Повтор через 10 мин` / `Retry in 10 min`, без активного retry. Tooltip явно: сервис разрешит повтор; unknown deadline не выдумывать. |
| Нужен вход / восстановление | `Нет доступа` / `Access issue` | `Восстановить доступ` / `Restore access` по действующему контракту; адресная инструкция нужного CLI. |
| Чтению Claude нужно разрешение | `Нужно разрешение` / `Permission needed` | До допуска ожидание, затем **`Разрешить` / `Allow`**. Полный tooltip/AX: `Разрешить доступ к Связке ключей · Claude Code` / `Allow Keychain access · Claude Code`. |
| Явное чтение ждёт разрешения | `Ждём разрешения…` / `Awaiting permission…` | **`Отменить` / `Cancel`**, полный AX: отменить запрос разрешения Claude Code. Не заменять обычной отменой сетевого refresh. |
| Отказ / отмена / timeout чтения | `Доступ не получен` / `Access not granted` | Только действие, которое разрешает текущее feedback; нового системного окна автоматически нет. |
| Не удалось сохранить обновлённый вход | `Вход не сохранён` / `Sign-in not saved` | `Восстановить доступ` / `Restore access`; подробности прямо говорят об ошибке сохранения, не об истёкшем входе. |

При сочетании причин брать приоритет и набор разрешённых действий из существующего feedback. Например, восстановление доступа может быть доступно при server wait, но retry сети — нет. Короткий footer не переопределяет этот приоритет.

## Время, действия и доступность

- Timestamp на экране/в tooltip: **HH:mm, без секунд**; при другой дате добавить `dd.MM HH:mm`. Это относится и к прежнему общему “updated”, если он показан. Countdown 30 с остаётся в секундах: это длительность защиты, а не timestamp.
- Tooltip области footer и её accessibility value содержат отдельно: `Данные: … / Data: …`, `Следующая автопопытка: … / Next automatic attempt: …`, полный статус и причину ожидания. При in-flight — `после ответа / after response`; неизвестное время `—`. Не подменять asOf временем нажатия; следующая попытка не гарантирует свежий ответ.
- Важные `Повторить`, `Восстановить доступ`, `Разрешить`, `Отменить` видны в карточке, доступны клавиатурой; tooltip хранит пояснение, не единственный путь к действию. AX labels действий содержат провайдера, видимые подписи его не повторяют.
- Для новых native-кнопок Tab/Shift+Tab следует визуальному порядку refresh → действия карточек; Enter/Space активируют один callback. Существующую settings-навигацию в этом исправлении не переписывать. Видимый focus не обрезается радиусом. Дочернее действие имеет приоритет над whole-card link: click не запускает ещё и переход в браузер/помощь.
- Глобальный refresh использует существующую per-provider admission: не дублирует in-flight, не обходит 30 с или Retry-After, допускает другой готовый сервис. Если все ожидают, нажатие лишь показывает существующее ожидание; если все выключены, refresh disabled с пояснением. Нажатие никогда не молчит без feedback.
- `Повторить` адресован только проблемному сервису. Ответ одного провайдера отображается сразу, второй продолжает ожидание. При обоих in-flight достаточно серой индикации у иконки/в footer; без нового баннера. Reduce Motion — статическая индикация вместо вращения.
- Обычный refresh остаётся quiet. Только отдельное `Разрешить` создаёт one-shot read permit до 15 с; `Отменить` завершает его без автоматического повтора. Разрешение чтения не разрешает запись. Открытие панели не становится manual intent; Auto/фиксированное расписание не переключается.
