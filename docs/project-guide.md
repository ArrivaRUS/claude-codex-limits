Принятый контракт ручного обновления Linux 0.4.5:

- Нажатие обходит локальные 15 минут, расписание Auto/фиксированного опроса и backoff после сетевой ошибки; выбранный режим сохраняется. Автоматический опрос учитывает ручную попытку и не создаёт немедленный дубликат.
- Защита 30 секунд от начала попытки и single-flight действуют отдельно для каждого провайдера. Повторные нажатия не создают параллельный запрос тому же сервису. Успешный ответ появляется сразу, не ожидая второго сервиса; после частичной ошибки доступен повтор только проблемного сервиса.
- Реальный серверный Retry-After соблюдается; известный срок показывается отдельно от локальной защиты и учитывается для автоматической попытки. Неизвестный срок не выдумывается.
- Неизменившиеся проценты в живом успешном ответе — успешное обновление. При fallback сохраняется старый `asOf`; неизвестное время остаётся `—`. Время данных и следующая автоматическая попытка показаны раздельно.
- При проблеме входа открыть «Восстановить доступ»: для Claude запустить `claude` и выполнить `/login`, для Codex — `codex login`. При ошибке чтения/сохранения проверить пользователя CLI, доступность файла входа и свободное место. Затем нажать «Повторить» для этого сервиса. Используются существующие Linux-файлы учётных данных; интерактивный вход и запрос разрешений автоматически не запускаются. macOS Keychain permit на Linux не используется.

## История выпусков — MANUAL-REFRESH: macOS 3.2.6

Версия 3.2.6 опубликована и установлена на Mac владельца 2026-10-07.
Публичный DMG совпадает с проверенным пакетом. Linux остаётся на 0.4.4.
Основание: [предложение и план](manual-refresh-proposal.md),
[результаты и ограничения проверки](manual-refresh-verification.md).

1. В Настройках включить нужные подписки; соответствующий CLI должен быть
   установлен и иметь действующий вход. Открыть простой или расширенный вид
   панели и нажать «Обновить сейчас» в шапке.
2. Ожидается «Обновляем…» отдельно у каждого включённого сервиса. Ответ одного
   сервиса отображается сразу, без ожидания другого. Прежние проценты после
   успешного ответа допустимы: важны результат и время показаний.
3. Читать «Данные» и «Следующая автопопытка» отдельно. При ошибке сохраняется
   прежний снимок с исходным временем, неизвестное время — `—`. Время нажатия
   не заменяет время получения данных; следующая попытка не гарантирует успех.
4. При частичной ошибке нажать «Повторить» у проблемного сервиса, когда ожидание
   закончится. Ручной запрос не ждёт интервала Auto/фиксированного опроса или
   локального сетевого backoff. Выбранный режим сохраняется. Уже идущий запрос
   не дублируется; локальная защита на 30 секунд считается от начала попытки.
5. «Повтор через…» относится к локальной защите. «Сервис разрешит повтор через…»
   относится к переданному сервером Retry-After: ручной запрос его не обходит,
   автоматическая попытка допускается по истечении срока. При неизвестном сроке
   нельзя приписывать серверу локальную паузу.
6. Только если чтению записи Claude нужно разрешение, после указанного ожидания
   появляется «Разрешить доступ к Связке ключей». Это отдельная попытка чтения
   до 15 секунд, в которой возможно системное окно. «Отменить» прекращает попытку;
   новый запрос требует нового нажатия. Разрешение чтения не разрешает запись
   обновлённых данных входа и не меняет права доступа автоматически.
7. При «Не удалось сохранить обновлённый вход» открыть «Восстановить доступ»,
   разблокировать Связку ключей и нажать «Обновить сейчас» для повтора сохранения. Успешное чтение
   не означает успешного сохранения. Ошибка чтения/записи сама по себе не требует
   входа заново. Если сохранение всё ещё не удаётся, новый `claude login` —
   дополнительный способ восстановления. При фактической проблеме входа выполнить инструкцию CLI:
   `claude login` для Claude или `codex login` для Codex, затем обновить данные.
   Эти команды здесь не выполнялись.

Обычное обновление по принятому контракту не запускает интерактивный вход или
системное разрешение. Для Claude добавлено отдельное явное действие чтения.
Восстановление доступа к лимитам не заменяет GitHub «Повторить доступ к Связке ключей»: контракт 3.2.5 ниже
сохраняется. Синхронизация истории имеет отдельное расписание.

Ограничения RAM и проверки перед записью описаны в [заметках 3.2.6](manual-refresh-release.md),
доказательства выпуска — в [реестре приёмки 3.2.6](manual-refresh-verification.md).
Проверки интерфейса 3.2.7 ведутся отдельно в его реестре приёмки.

Контракт требует no-UI для всех фоновых GitHub Keychain операций: V2 и legacy,
startup/wake, чтение, сохранение, проверка сохранённого и cleanup/GC. Если

откладывается. Недоступность не означает missing или отзыв входа. Прежний
процессный gate на 600 секунд лишь ограничивал частоту попыток; его окончание
или restart не разблокируют хранилище и не дают права показать окно.
Фоновые повторы должны оставаться без окон и после окончания паузы.

### Действия пользователя в версии 3.2.5

1. На Mac с версией 3.2.5 открыть Настройки → Синхронизация через GitHub и
   прочитать последнюю ошибку. При недоступности Связки ключей нажать
   «Повторить доступ к Связке ключей», не выходя из аккаунта.
2. Явная попытка ограничена по времени и может запросить системное разрешение.
   Разрешать только узнаваемому приложению доступ к указанной записи GitHub.
   Ожидаемый результат — проверка сохранённого входа, если доступ восстановлен;
   сетевой backoff и recovery-ограничения могут отложить синхронизацию.
3. Отмена/отказ завершает попытку без автоматического интерактивного повтора.
   Для нового запроса нужно новое нажатие. Если UI требует новый вход,
   выполнить его явно; это тоже ограниченное действие, не право для фоновых окон.

Существующим credentials может потребоваться ручное разрешение из-за изменения
identity помощника. «Разрешать всегда» относится к конкретной записи и
запрашивающему приложению, а не всему сервису или соседним поколениям записей.

Точная live-причина повторов после Always Allow у пользователя неизвестна:
изменение helper identity — возможная потребность при переходе, не диагноз случая.

## GitHub: работа и восстановление

Действующий старый долгоживущий вход продолжает работать без браузера и миграции
ради refresh. Только новый явный вход запрашивает `gist offline_access`; клиент
сохраняет refresh и сроки, если GitHub их выдал, и не выдумывает срок при отсутствии
полей. Продление короткого access выполняется автоматически из защищённой записи.
Автоматическая синхронизация и обслуживание входа независимы от Advanced и Auto
опроса лимитов; сканирование локальных журналов на Mac по-прежнему связано с Advanced.

После сна/restart следующая фоновая попытка заново проверяет срок и состояние
хранилища. Временные сеть/storage/429/5xx сохраняют последнюю надёжную выдачу;
повторы ограничены backoff, включая разрешённую issuer паузу. При доступных
зависимостях обычный цикл запускается раз в 10 минут; Mac также пытается после
пробуждения с задержкой около 7 секунд. Это расписание начала попытки, не гарантия
успешного запроса за 10 минут при rate limit или неисправном хранилище.

Если синхронизация остановилась: открыть Настройки → Синхронизация через GitHub,
прочитать последнюю ошибку и время успешного обмена. При недоступном хранилище
на Mac с версией 3.2.5 выбрать «Повторить доступ к Связке ключей»;
при ошибке сети восстановить соединение и дождаться фоновой попытки.
Фоновое расписание не разрешает системные окна и не гарантирует восстановление
после разблокировки. Одна ошибка или старые цифры не доказывают отзыв. При подтверждённом
невосстановимом отказе выполнить один явный вход там же (Linux: `ccl-sync login`).
Внешний отзыв, истёкший refresh, утрата локального ключа или потеря единственной
новой пары после принятого issuer refresh могут требовать ручного входа.
Неопределённый ответ сначала восстанавливается по сохранённому результату;
бюджет повторной issuer попытки ограничен, бесконечного reuse старого refresh нет.

Несовпадение identity блокирует публикацию чужого аккаунта. Сохранённая выдача
может пройти автоматическую повторную проверку: требуется новый успешный `/user`
с ID, совпадающим с известным аккаунтом текущей epoch. Постоянное несовпадение
не публикуется; новое подтверждение прежнего ID не является сменой аккаунта
и не требует нового OAuth grant или обязательного постоянного quarantine.

«Выйти» отключает только эту машину, не отзывает доступ приложения на GitHub
и не удаляет gist. Если физическая очистка не завершена, UI сообщает оставшийся
cleanup; повторить выход после доступности хранилища. Новые фоновый ответ или
запоздалый login не должны воскресить отключённую сессию. После restart Mac не
добавляет старый remote cache без подтверждения принадлежности входу: суммы
других машин появятся после первого подтверждённого обмена. Локальная история
сохранена. V2-кэш привязан к входу/аккаунту, чтобы не смешивать пользователей.

Длительный lifecycle проверяется синтетическими часами по тест-плану.
Это не доказательство шести месяцев реального использования или живого ALSE.

## Сборка, публикация и откат

macOS: `bash build.sh`, затем `./scripts/make-dmg.sh`; сверить версию `.app`, strict codesign и DMG. Linux: `sh linux/packaging/build-deb.sh` требует `dpkg-deb`. Если его нет на Mac, использовать DEB из успешного Ubuntu CI на точной принятой ревизии: проверить `headSha`, полный лог, имя, версию, архитектуру и SHA-256 скачанного `linux-deb`. Это отдельная проверка пакета, не живой ALSE smoke.

Для опубликованного выпуска используются macOS `v3.2.3` с `ClaudeCodexLimits-3.2.3.dmg`
и Linux `linux-v0.4.3` с `claude-codex-limits_0.4.3_all.deb`. Пакеты этих версий собраны и проверены;
публичные assets скачаны и совпадают с проверенными пакетами. Linux-релиз создаётся с `--latest=false`:
merge в `main` не обновляет пакетные установки, а Latest должен оставаться
macOS-релизом с DMG, который используют Mac updater и `get.sh`.
`sh linux/packaging/release.sh [notes-file]` требует проверенного main и `dpkg-deb`;
на Mac координатор может использовать проверенный пакет точной ревизии из CI.
Перед выпуском сверить версии, ревизию, отсутствие существующего тега и релиза;
после — публичные assets и SHA-256. Подготовленные [macOS notes](release-notes-3.2.3.md)
и [Linux notes](release-notes-linux-0.4.3.md). В notes записаны фактические проверки и SHA-256 локальных пакетов;
публикация завершена, публичные assets проверены; финальная bundled Mac QA: PASS.

Исторический выпуск GH-AUTH-STABLE — macOS `v3.2.3` и Linux `linux-v0.4.3` на exact source `40cfdf58980acef0668bdb4915c6001322ba9e11`.

сама по себе не доказывает восстановление GitHub-входа.
