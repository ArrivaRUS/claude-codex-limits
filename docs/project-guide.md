# Рабочий гайд проекта

Этот файл — маршрут следующей сессии, а не отметка о прохождении релизных гейтов. Текущая задача — видимая частота рядом с кнопкой Auto на macOS и Linux; её [спецификация](../design/auto-poll-ui.md) описывает UI, реализованный в рабочей версии macOS 3.2.1 / Linux 0.4.1; независимые проверки и публикация этой версии фиксируются отдельно в статусе. Опубликованные до этой задачи macOS 3.2.0 и Linux 0.4.0 не получили задним числом независимого командного ревью.

## Вход и роли

Если папка Юрки **подключена к рабочему пространству вместе с проектом**, режим включается автоматически. Одного её существования на диске недостаточно. На старте прочитать [AGENTS HQ](../../2026.06%20Юрка/AGENTS.md) и [режим только Codex](../../2026.06%20Юрка/handoff/references/codex-only.md), установить абсолютный `PROJECT_ROOT=/Users/arrivarus/Documents/VibeCoding2/2026_06_UsageLimits`, затем прочитать [AGENTS проекта](../AGENTS.md), [локальную инструкцию команды](codex-team.md), [HQ/now](../../2026.06%20Юрка/HQ/now.md), [HEARTBEAT](../HEARTBEAT.md), [решения](../decisions/log.md), [индекс уроков](../.patches/INDEX.md) и план задачи. Исторические пути и статусы сверить с checkout и `git status`. [HANDOFF](../../2026.06%20Юрка/handoff/HANDOFF.md) сохраняет контекст общих правил и уроков; его mixed-назначения моделей и способов запуска здесь не применяются.

Главная сессия — Юрка-оркестратор: брифует, сводит отчёты, проверяет результат и ведёт память. Штатный профиль координатора — GPT-6 Astra / medium; фактическую модель выбирают в клиенте. Запись конфигурации сама по себе не переключает уже запущенную сессию. Производящую работу выполняют отдельные native Codex-субагенты с одной ролью и узкой областью записи. Developer, независимые CodeReviewer и Tester, QA, TechWriter не совмещаются в одном исполнителе; специалисты не запускают подагентов, не общаются друг с другом и не делают Git-мутаций без отдельного поручения.

Канон запуска — [AGENTS](../AGENTS.md), [docs/codex-team.md](codex-team.md), [.codex/config.toml](../.codex/config.toml) и профили [.codex/agents](../.codex/agents/). Штатно установлены 21 роль, конфигурация и инструкция: проверка установщика подтвердила 23 файла. При запуске передавать модель/effort и ограничения из выбранного TOML; если именованные роли не подхватились, читать профиль и передавать его инструкции обычному субагенту. Для отличающейся модели использовать отдельный контекст и явное назначение, а не механизм полного наследования модели родителя. `CLAUDE.md`, `.claude/` и `codex-bridge` относятся к историческому mixed-режиму и не являются рабочими инструкциями или средствами запуска. Claude, Gemini, OpenRouter и мосты к другим движкам не запускать.

## Проверки без доступа к живым данным

Перед запуском прочитать [урок 006](../.patches/006-tests-touch-real-keyring.md) и [план проверок](test-plan.md). Временные `XDG_*` сами по себе **не** изолируют KWallet, gist и файлы входа CLI. Linux-тесты должны импортировать `linux/tests/_isolate.py` **до** `ccl`; для `TrayApp` и `sync`/`vault` заглушить secret service, чтение токена, синхронизацию и сеть по образцу `linux/tests/gui_width_probe.py`. Не читать реальные журналы и credentials, не вызывать `/usr/bin/security`, не делать живых запросов к API/gist. Для macOS допустима только подтверждённая исходниками безопасная ветка `--subscriptions-selftest` с временным бинарём: volatile `UserDefaults` в `NSArgumentDomain`, временные фикстуры, `OFFLINE_SYNC_HTTP` и `OfflineSyncKeychain` исключают живые API/Keychain. Перед запуском новой ревизии сверить сохранение этой изоляции. Обычное приложение и старые небезопасные preview-флаги не запускать. Дополнительный профиль `sandbox-exec` допустим как защита после проверки его совместимости; произвольный непроверенный профиль не становится обязательным гейтом. Отказ sandbox на self-mapping AppKit фиксировать как ограничение среды, а не дефект продукта и не PASS selftest. Фактический результат безопасного selftest учитывать отдельно.

После реализации сначала запустить целевые наборы, затем полную suite ровно по [командам тест-плана](test-plan.md). На macOS может не быть PyQt5, Breeze или `dpkg-deb`: пропуски GUI/DEB **не** означают PASS. [Linux CI](../.github/workflows/linux.yml) на Ubuntu 22.04 ставит PyQt5, dbus и Breeze, запускает `/usr/bin/python3 -m unittest discover -s linux/tests -v`, собирает DEB и сохраняет previews. CI подтверждает свои проверки, а не реальный KDE/ALSE. Живой прогон ALSE остаётся открытым, пока его фактически не выполнит подходящая машина.

Для каждого гейта сохранить в [статусе](status.md) ревизию, точную команду, exit code, сырой вывод или ссылку на полный лог, число `run`/`skipped`, артефакты и незакрытые пункты. Текущей правке нужны независимые Tester/CodeReviewer, визуальная QA-матрица macOS/Linux × RU/EN × Simple/Advanced, отсутствие неверной рамки ручного слота и подпись актуального per-product интервала. Исторические 205 Linux-тестов и Swift selftest на `e6e2f2e` не подтверждают новую ревизию; непроведённый прогон не записывать как PASS.

## Сборка, выпуск и откат

На macOS `bash build.sh` собирает `.app` в `dist/`, а `./scripts/make-dmg.sh` собирает и проверяет подписанную ad-hoc `.app`, затем создаёт DMG. Версию перед выпуском сверить между `build.sh`, `scripts/make-dmg.sh` и заметками. На Linux `sh linux/packaging/build-deb.sh` берёт версию из `linux/ccl/__init__.py` и требует `dpkg-deb`. При отсутствии `dpkg-deb` на Mac использовать успешный Linux CI на точной выпускаемой ревизии: он собирает DEB и сохраняет артефакт `linux-deb`. Сверить SHA запуска, полный лог тестов и упаковки, скачать именно его пакет и проверить имя, версию, архитектуру и контрольную сумму. Локальная сборка DEB на Mac для этого маршрута не требуется.

Публикация Linux-пакета — отдельный шаг после проверенного `main`: `sh linux/packaging/release.sh [notes-file]` проверяет совпадение с `origin/main`, собирает DEB и создаёт релиз `linux-v<версия>` с `--latest=false`. При публикации с Mac можно загрузить проверенный DEB успешного CI через `gh`, без запуска `build-deb.sh`/`release.sh` на Mac:

```sh
gh run view <run-id> --json headSha,conclusion,url
gh run download <run-id> --name linux-deb --dir <temporary-artifact-dir>
gh release create linux-v<версия> <temporary-artifact-dir>/<проверенный-файл.deb> --target <проверенный-SHA-main> --latest=false --title "Linux <версия>" --notes-file <notes-file>
```

Это шаблоны команд, не запись выполненного выпуска. До `release create` подтвердить `conclusion=success`, совпадение `headSha` с принятой ревизией `main`, отсутствие существующего тега/релиза и соответствие версии пакета заметкам. Один merge в `main` пакетную установку не обновляет. **Latest должен оставаться macOS-релизом с DMG**: Mac updater и `get.sh` ищут DMG через `releases/latest`. Перед публикацией сверить тег, версии, состав артефактов и поведение `releases/latest`; после — скачать/установить артефакт и выполнить smoke ключевого сценария с фиксацией результата.

Цели отката — предыдущие проверенные релизы macOS `v3.2.0` (`ClaudeCodexLimits-3.2.0.dmg`) и Linux `linux-v0.4.0` (`claude-codex-limits_0.4.0_all.deb`). На Mac закрыть приложение и заменить `.app` копией из прежнего DMG. На Linux установить скачанный прежний DEB через `sudo apt install --allow-downgrades ./claude-codex-limits_0.4.0_all.deb`, сверив предложенные apt изменения до подтверждения. Не удалять настройки и пользовательские данные. Этот UI-инкремент не меняет формат сохранённого состояния Auto; отдельная миграция не требуется. Фактическую переустановку и её smoke фиксировать отдельно; до выпуска записать условия остановки/отката. При неуспешном smoke остановить распространение новой версии, вернуть известный рабочий пакет на затронутой машине, проверить ключевой сценарий и занести факт в [журнал решений](../decisions/log.md) и [статус](status.md). Не подменять эти действия непроверенной командой отката и не заявлять реальный ALSE-прогон без его вывода.
