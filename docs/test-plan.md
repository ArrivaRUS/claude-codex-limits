# План проверок — частота рядом с «А»

Дата: 2026-10-03. База до реализации: `e6e2f2e`. План составлен **до изменения кода** по прямому запросу владельца, [`../PRD.md`](../PRD.md) и уточнению оркестратора: рядом с «А» нужна текущая частота; пояснение backoff остаётся в существующей подсказке. Для одной подписки или одинаковых интервалов допустимо одно время без имён. При разных интервалах обязательна явная привязка Claude Code/Codex. Новая клавиатурная или accessibility-реализация в этот инкремент не входит. Визуальные параметры берём из будущей UX-спецификации; этот план не выбирает их.

## Фикстуры и ожидаемое поведение

Все состояния задаются в памяти, с контролируемым временем, без живых CLI-журналов и учётных данных. Интервалы — секунды из `PollState`/`AutoPollState`, а не сохранённый ручной `interval` и не текст tooltip.

| Фикстура | Подписки и Auto | Ожидание на панели |
|---|---|---|
| F1 | Claude 900, Codex 14400; обе включены, Auto on | «А» активна; рядом `Claude Code 15м · Codex 4ч` (EN: `15 min`, `4 h`); ручные слоты не активны. Имена однозначно связаны со своими числами. |
| F2 | обе 1800; обе включены, Auto on | Достаточно одного `30м` / `30 min`; показ не должен намекать на разные частоты. |
| F3 | только Claude 3600 **или** только Codex 900; Auto on | Только `1ч` / `1 h` либо `15м` / `15 min`; выключенный продукт не заявлен. |
| F4 | обе выключены, сохранён Auto on | Явная пауза опроса, без действующей динамической частоты. |
| F5 | Auto off; сохранены 900, 1800, 3600 по очереди | Активен ровно выбранный ручной слот, динамической подписи у «А» нет; переключение обратно в Auto не меняет сохранённое ручное значение. |
| F6 | Claude failed с интервалом 3600, Codex 900; Auto on | Рядом с «А» верные `Claude Code 1ч · Codex 15м` (EN единицы соответствуют). Существующий tooltip объясняет backoff только Claude; число Claude остаётся фактическим интервалом, без обещания точного следующего запроса. |
| F7 | Начало с F1; затем `observe`/`localActivity` меняет один интервал, либо меняется выбор подписок/режим; также восстановление сохранённых состояний | При следующей перерисовке надпись берётся из нового состояния без перезапуска и без устаревшего значения другого продукта. |

## Минимальное автоматическое покрытие после реализации

| Истории / риск | Проверка и место |
|---|---|
| UI-1, UI-2: F1–F4 | Один компактный набор таблиц состояний в `linux/tests/test_subscriptions.py` и в существующем Swift `--subscriptions-selftest`: проверять **наблюдаемое** содержимое/источник подписи и выбранный сегмент. Различающиеся интервалы должны быть подписаны именами; равные/одиночные — читаемым временем; обе выключены — пауза. Без теста на конкретный цвет, радиус или положение каждого пикселя. |
| UI-3: F6 | Добавить по одному проверочному случаю на платформу для актуального интервала при failed/backoff и существующего tooltip. Уже имеющиеся `linux/tests/test_auto_polling.py` и Swift selftest проверяют сам переход в backoff; лестницу Auto повторно не тестировать. |
| UI-4: F5, RU/EN, Simple/Advanced | Проверить выбранность сегментов и отсутствие динамической подписи в Manual на обеих платформах. Рендеры F1/F2/F4/F6 в обоих языках и видах оценивать глазами по UX-спецификации: «А» различима, подпись рядом, текст не обрезан, нет пересечения с `updated`, `power`, нижней строкой credits. Для Linux расширить существующую проверку `test_panels_all_selections_and_intervals`; для macOS — имеющийся offline selftest и изображения в `/tmp`. |
| Изменение state → view: F7 | Один тест связки на платформу: инъекция новых per-product состояний → реальный вызов обновления модели/панели → чтение нового отображаемого текста. Проверять обновление после ответа и после смены подписки; не ограничиваться вызовом чистого formatter. |
| Сохранение расписания и числа запросов | Сравнить вызовы `refresh_limits`/`doRefresh` для F1, F5, F6 с действующими контрольными тестами. `test_auto_polling.py` уже проверяет независимость, due/floor/backoff и отсутствие запросов выключенным продуктам; новые UI-тесты не должны вызывать сеть. Ревью диффа подтверждает отсутствие изменений `polling.py`, Swift `AutoPollState`, таймеров и fetch-кода. |

## Изоляция — обязательна до любого запуска

- Linux: `linux/tests/_isolate.py` импортируется **первым** до `ccl`, задаёт временные `XDG_*`, глушит `vault._ss`, `sync.transport`, `common.http` и перенаправляет CLI-пути. Для теста с `TrayApp` дополнительно заглушить `vault.read`, `vault._file_get`, `sync.sync_cycle`, оба `limits.fetch_*`, `usage.refresh`; брать схему из `linux/tests/gui_width_probe.py`. `test_zz_isolation.py` сверяет лишь наличие/mtime реальных файлов, не читает их содержимое. Никаких реальных keyring, gist/API, пользовательских логов и `/usr/bin/security`.
- macOS: запускать только `--subscriptions-selftest` на собранном временном бинаре после подтверждения offline-ветки в коде: volatile `UserDefaults`, временные фикстуры журналов, `OFFLINE_SYNC_HTTP` и `OfflineSyncKeychain`. Не запускать старые `--settings-preview`, `--advanced-preview`, общий `--preview`, обычное приложение или живые запросы. Рендеры сохранять только в `/tmp`; **не** перезаписывать эталонные `docs/*.png`. Использовать ограничивающий профиль `sandbox-exec` ниже; если он недоступен или не работает, selftest не запускать и отметить проверку как открытую.
- Ошибка изоляции, отсутствие PyQt5 или отсутствие Swift toolchain = соответствующая проверка **не выполнена**, а не PASS. Linux GUI-`skip` не засчитывается за проверку интерфейса.

## Команды для этапа тестирования (после кода)

Запускать из корня проекта; команды сейчас записаны, **не запускались**. Перед запуском убедиться, что новые тесты сохраняют первый импорт `_isolate` и не открывают реальные хранилища/сеть. Рендеры — временные артефакты.

```sh
QT_QPA_PLATFORM=offscreen CCL_PREVIEW_DIR=/tmp/ccl-auto-ui python3 -m unittest discover -s linux/tests -p 'test_subscriptions.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -p 'test_auto_polling.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -p 'test_gui_layout.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -v
```

Полную Linux suite запускать один раз после целевых тестов, записать ревизию, exit code, число `run` и `skipped`. Если на macOS нет PyQt5/Breeze, GUI-проход повторить на Linux с PyQt5 и Breeze. `gui_width_probe.py` уже вызывается `test_gui_layout.py` в отдельном процессе с offscreen-фейками; он проверяет страницу настроек. Панель Simple/Advanced и перекрытия оценивать по новым `/tmp/ccl-auto-ui/*.png` и по живой панели на подходящей машине.

```sh
mkdir -p /tmp/ccl-auto-ui
/usr/bin/swiftc -O Sources/LimitsMonitor.swift -o /tmp/ccl-auto-ui/LimitsMonitor-selftest
cat > /tmp/ccl-auto-ui/offline.sb <<'EOF'
(version 1)
(allow default)
(deny network*)
(deny mach-lookup (global-name "com.apple.securityd"))
(deny file-read* (subpath "/Users/arrivarus/.claude"))
(deny file-read* (subpath "/Users/arrivarus/.codex"))
(deny file-read* (subpath "/Users/arrivarus/.config/claude-codex-limits"))
(deny file-read* (subpath "/Users/arrivarus/.local/state/claude-codex-limits"))
(deny file-write* (subpath "/Users/arrivarus"))
EOF
sandbox-exec -f /tmp/ccl-auto-ui/offline.sb /tmp/ccl-auto-ui/LimitsMonitor-selftest --subscriptions-selftest
```

Критерий результата: на новой ревизии целевые проверки и полная доступная suite без ошибок и без непредвиденных `skip`; Swift selftest завершился 0; изображения и живая панель читаемы по матрице; сетевых вызовов и касаний пользовательских секретов нет. Исторические **205 Linux-тестов + Swift selftest на `e6e2f2e`** — лишь предыдущая фактура, не PASS этой правки. Реальная ALSE сейчас недоступна; её живой прогон остаётся отдельным открытым пунктом, никакой симуляцией он не закрывается. Независимый аудит ранее выпущенного Auto также отдельная задача.
