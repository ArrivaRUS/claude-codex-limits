# План проверок — частота рядом с «А»

Дата: 2026-10-03. База до реализации: `e6e2f2e`. План составлен **до изменения кода** по прямому запросу владельца, [`../PRD.md`](../PRD.md) и уточнению оркестратора; уточнён по [`../design/auto-poll-ui.md`](../design/auto-poll-ui.md) и [`auto-ui-implementation.md`](auto-ui-implementation.md). Рядом с «А» нужна текущая частота; пояснение backoff остаётся только в существующей подсказке. Для одной подписки или одинаковых интервалов показывается одно краткое время без имён. При разных интервалах обязательна явная привязка Claude/Codex. Новая клавиатурная или accessibility-реализация в этот инкремент не входит; статичный контур, существующие cursor/tooltip сохраняются.

Исполнение — только Codex по `AGENTS.md`, `docs/codex-team.md` и каноническим `.codex/agents/*.toml` HQ/проекта. Старые mixed-настройки и `.claude/` bootstrap неактивны. Существенный код делает Developer; независимый Tester проверяет фиксированную ревизию/диф, не принимает отчёт автора за собственную проверку.

## Фикстуры и ожидаемое поведение

Все состояния задаются в памяти, с контролируемым временем, без живых CLI-журналов и учётных данных. Интервалы — секунды из `PollState`/`AutoPollState`, а не сохранённый ручной `interval` и не текст tooltip.

| Фикстура | Подписки и Auto | Ожидание на панели |
|---|---|---|
| F1 | Claude 900, Codex 14400; обе включены, Auto on | «А» активна; рядом `Claude 15м · Codex 4ч` (EN: `Claude 15m · Codex 4h`); пробелы вокруг `·`; ручные слоты не активны. Имена однозначно связаны со своими числами. |
| F2 | обе 1800; обе включены, Auto on | Одно `30м` / `30m`; показ не должен намекать на разные частоты. |
| F3 | только Claude **или** только Codex; каждый из 900/1800/3600/14400; Auto on | Только `15м` / `30м` / `1ч` / `4ч` (EN: `15m` / `30m` / `1h` / `4h`); выключенный продукт не заявлен. |
| F4 | обе выключены, сохранён Auto on | Рядом `нет подписок` / `no subscriptions`; Auto остаётся переключаемым, действующей динамической частоты нет. |
| F5 | Auto off; сохранены 900, 1800, 3600 по очереди | Активен ровно выбранный ручной слот, динамической подписи у «А» нет; переключение обратно в Auto не меняет сохранённое ручное значение. |
| F6 | Claude failed с интервалом 3600, Codex 900; Auto on | Рядом с «А» верные `Claude 1ч · Codex 15м` (EN: `Claude 1h · Codex 15m`). Существующий tooltip объясняет backoff только Claude; описание ошибки отсутствует в строке. Число Claude остаётся фактическим интервалом, без обещания точного следующего запроса. |
| F7 | Начало с F1; затем `observe`/`localActivity` меняет один интервал, либо меняется выбор подписок/режим; также восстановление сохранённых состояний | При следующей перерисовке надпись берётся из нового состояния без перезапуска и без устаревшего значения другого продукта. |
| F8 | `updated` задано либо nil; Auto on/off | Auto on: `обновлено HH:MM` / `updated HH:MM` только в tooltip при известном времени, отсутствует в строке; при nil строки времени в tooltip нет. Auto off: прежняя отметка времени в футере сохраняется. |

Расширить F1/F2 до всех 16 пар четырёх интервалов; одинаковые пары всегда дают одно значение. Порядок разных пар всегда `Claude … · Codex …`, без `Claude Code`, `C/X`, `min` или пробела перед единицей. F1–F8 проходят в RU/EN × Simple/Advanced и fallback Advanced → Simple. Manual=3600 при Auto=900/14400 не меняет источник подписи; Auto off возвращает manual-выделение. Startup restored=14400/900 при not-due показывает восстановленные значения; отсутствующее состояние — 1800 (`30м`/`30m`). Переключение подписок и открытие панели обновляют подпись без нового запроса.

## Изоляция — обязательна до любого запуска

- Linux: `linux/tests/_isolate.py` импортируется **первым** до `ccl`, задаёт временные `XDG_*`, глушит `vault._ss`, `sync.transport`, `common.http` и перенаправляет CLI-пути. Для теста с `TrayApp` дополнительно заглушить `vault.read`, `vault._file_get`, `sync.sync_cycle`, оба `limits.fetch_*`, `usage.refresh`; брать схему из `linux/tests/gui_width_probe.py`. `test_zz_isolation.py` сверяет лишь наличие/mtime реальных файлов, не читает их содержимое. Никаких реальных keyring, gist/API, пользовательских логов и `/usr/bin/security`.
- macOS: оркестратор запускает только существующий полностью offline `--subscriptions-selftest` на собранном временном бинаре после подтверждения этой ветки в текущем коде: volatile `UserDefaults` в `NSArgumentDomain`, временная fixture root с явным `UsageLogs.scan(home: root)`, `OFFLINE_SYNC_HTTP` и `OfflineSyncKeychain`; ветка не запускает обычный AppDelegate. Сеть, реальные credentials/keyring и пользовательские logs запрещены. Не запускать старые `--settings-preview`, `--advanced-preview`, общий `--preview`, обычное приложение или живые запросы. Рендеры сохранять только в `/tmp`; **не** перезаписывать эталонные `docs/*.png`.
- `sandbox-exec` — дополнительное ограничение при фактической доступности и совместимости, а не обязательный непроверенный гейт. Профиль ниже — кандидат для отдельного пробного запуска; фиксировать его результат отдельно. AppKit abort/недоступность WindowServer в sandbox не доказывает дефект приложения и не разрешает касаться настоящих credentials. Оркестратор может повторить ту же подтверждённую offline selftest-ветку с необходимой эскалацией AppKit; обычное приложение и unsafe previews остаются запрещены.
- Нарушенная offline-изоляция, отсутствие PyQt5 или отсутствие Swift toolchain = соответствующая проверка **не выполнена**, а не PASS. Linux GUI-`skip` не засчитывается за проверку интерфейса. Если AppKit так и недоступен, рендер/selftest остаются открытыми с точной причиной среды.

## Команды для этапа тестирования (после кода)

Запускать из корня проекта; команды сейчас записаны, **не запускались**. Перед запуском убедиться, что новые тесты сохраняют первый импорт `_isolate` и не открывают реальные хранилища/сеть. Рендеры — временные артефакты.

```sh
QT_QPA_PLATFORM=offscreen CCL_PREVIEW_DIR=/tmp/ccl-auto-ui python3 -m unittest discover -s linux/tests -p 'test_subscriptions.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -p 'test_auto_polling.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -p 'test_gui_layout.py' -v
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s linux/tests -v
```

Полную Linux suite запускать один раз после целевых тестов, записать ревизию, exit code, число `run` и `skipped`. Если на macOS нет PyQt5/Breeze, GUI-проход повторить на Linux с PyQt5 и Breeze. `gui_width_probe.py` уже вызывается `test_gui_layout.py` в отдельном процессе с offscreen-фейками; он проверяет страницу настроек. Панель Simple/Advanced и перекрытия оценивать по новым `/tmp/ccl-auto-ui/*.png` и по живой панели на подходящей машине.

```sh
mkdir -p /tmp/ccl-auto-ui
/usr/bin/swiftc -O Sources/LimitsMonitor.swift -o /tmp/ccl-auto-ui/LimitsMonitor-selftest
```

После проверки изоляции в текущем коде оркестратор запускает безопасную ветку, при необходимости с доступом AppKit:

```sh
/tmp/ccl-auto-ui/LimitsMonitor-selftest --subscriptions-selftest
```

Дополнительный sandbox-прогон — только если `sandbox-exec` доступен и профиль совместим с AppKit; недоступность или abort записать отдельно, затем применить порядок выше:

```sh
cat > /tmp/ccl-auto-ui/offline.sb <<'EOF'
(version 1)
(allow default)
(deny network*)
(deny mach-lookup (global-name "com.apple.securityd"))
(deny file-read* (subpath "/Users/arrivarus/.claude"))
(deny file-read* (subpath "/Users/arrivarus/.codex"))
(deny file-read* (subpath "/Users/arrivarus/.config/claude-codex-limits"))
(deny file-read* (subpath "/Users/arrivarus/.local/state/claude-codex-limits"))
(deny file-write* (subpath "/Users/arrivarus"))
EOF
sandbox-exec -f /tmp/ccl-auto-ui/offline.sb /tmp/ccl-auto-ui/LimitsMonitor-selftest --subscriptions-selftest
```

Критерий результата: на новой ревизии целевые проверки и полная доступная suite без ошибок и без непредвиденных `skip`; Swift selftest завершился 0; изображения и живая панель читаемы по матрице; сетевых вызовов и касаний пользовательских секретов нет. Исторические **205 Linux-тестов + Swift selftest на `e6e2f2e`** — лишь предыдущая фактура, не PASS этой правки. Реальная ALSE сейчас недоступна; её живой прогон остаётся отдельным открытым пунктом, никакой симуляцией он не закрывается. Независимый аудит ранее выпущенного Auto также отдельная задача.
