## 2. Новые находки

### N5 · major (Sol; моя оценка minor, взята строже) · обрыв во время PATCH №1 первой сессии — опроса нет никогда
- **Где.** `publisher.py:330` — резерв (`_save`), `:335` — `_publish`. Счётчик и решение о fallback (`:336–344`) появляются только после возврата `_publish`. Даже если на диске уже `_publishFailures=3`, проход сначала блокируется на PATCH №1.
- **Вектор.** Публикация детерминированно не доходит до конца:
  - лимит юнита A4 (`RuntimeMaxSec`/`TimeoutStartSec`) меньше, чем чтение + PATCH, а это ≈ 2 мин;
  - или PATCH не завершается сам: DNS не ограничен `timeout`, тело ответа PATCH читается без `deadline=`, только с посокетным сроком 20 с. Медленная передача на пути или зависший GitHub держат проход, пока его не убьёт юнит.

  На каждом due-тике остаётся консервативный резерв без запроса. Следов нет: `publish_failed`, `pass_failed` и `lastError` пустые.
- **Воспроизведение P5g.** `Kill` внутри PATCH с новым `attemptAt` на каждом due-тике, 2 суток: **0 опросов**, `_publishFailures` на диске нет. Sol независимо: 0 опросов за 577 тиков, в том числе при старте с 3.
- **Фикс** (вместе с P1 ревьюера — одна семантика счётчика):
  - (а) +1 к счётчику пишется тем же `_save`, что и резерв (`:330`), до PATCH №1. 0 пишется на диск сразу после подтверждённого PATCH №1, до провайдера. Это закрывает и путь P1 «убит во время провайдера».
  - (б) Если на входе счётчик ≥ 3 или сработала ветка «≥ max(I, 24 ч)», опрос идёт **до** блокирующей публикации, объявление — после, как heartbeat.
  - (в) В A4 `RuntimeMaxSec` ≥ 15 мин. Это дополнительная мера, одной её мало.
- **Тест.** A3-49, см. §4.

### N6 · minor (= n2 ревьюера; у него nit, у меня minor из-за потери одноразового refresh)
- **Где.** `common.py:975`. Срок заголовков отсчитывается от входа в `http()` и включает DNS, connect, TLS и отправку тела.
- **Проба.** DNS 1,2 с + ответ сервера через 1,0 с, timeout 2 → POST на токен-эндпоинт получает `HTTP_DEADLINE` в 3 случаях из 3. С быстрым DNS — 200 в 3 из 3.
- **Последствие.** Refresh-токен издатель уже потратил, новая пара потеряна. Пользователь входит заново. Для Anthropic и OpenAI это касается только машин с `guarded`; refresh GitHub идёт на всех машинах, включая VPS.
- **Фикс.** Без явного `deadline=` считать срок заголовков от создания ответа, то есть после отправки запроса. Явный срок sync оставить как есть.
- **Тест.** A3-50. Долг A4.

### N7 · minor, существовало до дифа (Sol) · тело 3xx в updater читается целиком
- **Где.** `common.py:985`. Для URL не из gist с `follow_redirects=True` работает штатный `HTTPRedirectHandler`. Он вызывает `fp.read()` до `_read_http_body`, без предела и без общего срока. Это затрагивает `update.py:101`, `:118`, `:215`, `:238`.
- **Проба Sol.** 302 с телом 1 МиБ, `max_body=32` → прочитан 1 МиБ.
- **Оценка.** Источник — GitHub по TLS. Исчерпание памяти updater возможно только через враждебный прыжок редиректа.
- **Фикс.** Свой обработчик для updater, как `_GistRawRedirect`:
  - тело 3xx закрывать непрочитанным;
  - не больше N прыжков;
  - цель только HTTPS из белого списка.

  Долг A4.

### N8 · minor · долг тестовой изоляции (находка tester)
