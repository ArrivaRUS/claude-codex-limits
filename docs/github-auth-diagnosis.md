- [x] SecurityAnalyst GPT-6 Astra/high: официальные правила GitHub OAuth, независимая сверка вида приложения и исторической гипотезы.
- [x] SecurityAnalyst независимо сверил Linux GUI storage-path и сводку: PASS, область дефекта уточнена до `_ss() is None`.
- [x] Координатор: выводы сопоставлены; дальнейший безопасный шаг записан, результат исследования готов для ответа. Диагноз конкретной машины остаётся открытым.

Без реальных credentials/keyring/defaults/журналов и auth/API вызовов. Specialist только readonly. Факт прошлого инцидента не доказывает повторение причины сегодня. Чтение документации GitHub разрешено. Изоляция — уроки 006/007.

## Подтверждённые пути кода

1. Серверный путь утраты входа: API 401 → GET /user 401 → пауза 4 секунды → GET /user 401. Только затем revoked и адресное удаление локальной копии. Любой non-401 прекращает подтверждение. Swift `Sources/LimitsMonitor.swift:1626`, Linux `linux/ccl/sync.py:428`. Это классификация утилиты, а не объяснение недействительности токена.
2. macOS ставит UI revoked также при missing записи Keychain и известном syncLogin **без серверного 401** (`Sources/LimitsMonitor.swift:1387`, `:1759`). Заголовок «Вход в GitHub отозван» (`:3931`) не доказывает серверный отзыв. LastError различает причины. Timeout/failure сохраняют .on; timeout вводит backoff 30 минут.
3. Linux: выбран backend secret-service, известен login, нет revoked/pending cleanup, а сервис отсутствует именно по пути `_ss() is None` → `vault._ss_read` даёт `(None, False)` → `_read` даёт `(None, None)`. Sync проверяет `reachable` и сообщает unavailable (`linux/ccl/sync.py:506`), а GUI без такого различения показывает «Войти через GitHub» (`linux/ccl/gui/app.py:552`, `:578`, `:603`). Timeout/exception возвращают различимый backend и уже обработаны GUI; находка не относится ко всем ошибкам SS. Показ кнопки сам по себе не удаляет токен и не запускает device flow. Debugger воспроизвёл это pure AST: synthetic settings, mock отсутствующего SS и Qt objects; без импорта ccl/HTTP/DBus/keyring/threads. SecurityAnalyst независимо подтвердил путь статически. Это подтверждённый путь ошибочной подсказки, **не диагноз окружения пользователя**.
4. Обе платформы используют OAuth App, scope gist, общий client ID. Swift (`:1455`, `:1472`, `:1481`) и Linux (`sync.py:124`, `:147`) сохраняют только access_token; возможные refresh_token/expires_in не используются. Если реальный OAuth App выдаёт истекающие токены, будет нужен периодический ручной перевход. Настройка приложения **не проверена**.
5. Автоматической выдачи новых токенов не найдено: device flow только по явному входу пользователя. Auto 15/30/60/240 минут обновляет лимиты; GitHub синхронизация работает отдельно, раз в 10 минут. Auto не устраняет вышеописанные пути.
6. Выход только локальный по решению владельца. Повторные входы могут накапливать серверные выдачи; достижение лимита пользователем не доказано. Локальные generations защищают от удаления нового токена старой операцией, а не от серверной политики. Linux CLI также может сказать Already signed in по сохранённому login без проверки missing token (`linux/ccl/cli.py:60`).

## Официальная policy GitHub — проверено 2026-10-04

- Не более 10 токенов на user/app/scopes. При избытке GitHub выбирает старый неиспользованный токен старше минуты, иначе наименее недавно использованный, иначе самый старый. Отдельный лимит 10 выдач в час вызывает браузерное повторное подтверждение и сам по себе старый токен не отзывает. Историческое «всегда самый старый» неточно. [Creating multiple tokens](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#creating-multiple-tokens-for-oauth-apps).
- OAuth Apps тоже поддерживают опциональные access tokens на 8 часов и refresh tokens. Оба flow могут получать их при offline_access или глобальной optional feature. Наш scope только gist, но глобальная настройка может применяться к новым выдачам. Её включение не сокращает жизнь уже выпущенных бессрочных токенов. [Expiring access tokens](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#expiring-access-tokens).
- Другие причины: ручной отзыв, отзыв GitHub/приложением, публичная утечка, год без использования. Событие oauth_authorization.destroy **может** появиться в Security log; отсутствие события не доказывает отсутствие отзыва. [Token expiration and revocation](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/token-expiration-and-revocation).

## Дальнейший безопасный шаг

Нужны платформа/версия, точный текст последней ошибки без секретов, время после успешного входа, связь с запуском/разблокировкой wallet или входом на другой машине. При периоде около 8 часов — проверить только optional feature OAuth App (не переключать её) и готовить поддержку refresh по отдельному контракту. При запуске Linux — различать unavailable хранилища и отсутствие записи. При server 401 сопоставить время с типом события GitHub Security log, без полного экспорта IP/почты. Токены, device codes и auth headers не нужны; массовый revoke не предлагается.

Исправление storage UI / refresh требует отдельного подготовленного контракта и проверки. Ранее выбранная политика logout сохраняется. Production не изменялся, release-suite не перезапускалась. Реальные аккаунты и хранилища не проверены.
