## 3. Новые риски, внесённые правками (STRIDE-lite)

### R1 — major · вне дифа A1, pre-existing, обязательна для A2 · Bearer-токены Anthropic/OpenAI уходят на любой хост при редиректе; тела 3xx дренируются без предела
`limits.py:243–245` и `:550–552`: `common.http(…, "GET", {"Authorization": "Bearer " + at, …})` без `follow_redirects=False` и без `max_body` → `common.py:490` стоковый `urlopen` → `HTTPRedirectHandler.redirect_request` (CPython 3.14, `urllib/request.py:647–651`) копирует **все** `req.headers`, включая `Authorization`, в запрос на новый URL любого хоста (`http`/`https`/`ftp`), а `http_error_302` делает `fp.read()` без предела.
- **Вектор (Information disclosure):** 30x от `api.anthropic.com` / `chatgpt.com` (или MITM с валидным сертификатом) → OAuth-токен Claude или Codex уходит на чужой хост. Вероятность низкая (хост провайдера), ущерб высокий — это доступ к аккаунту, а не DoS, как в N3.
- **Воспроизведение (офлайн, in-memory сервер):** `common.http("https://api.example/x", headers={"Authorization": …})`, 302 → `https://evil.example/y`: второй запрос ушёл **с** `Authorization`, тело 302 прочитано без предела (33 МиБ до остановки заглушки). Через `sync._transport` тот же сценарий не воспроизводится (`_NoRedirect`).
- **Фикс (A2 — это код сбора лимитов, который A2 и трогает):** `follow_redirects=False` и `max_body=16 МиБ` для всех авторизованных вызовов `limits.py` (эндпоинты не редиректят); `update.py:215`, `:238` — `max_body=MAX_DEB` / `MAX_TARBALL` вместо чтения всего тела в память.
- **Тест-на-атаку (A2):** авторизованный GET получает 302 → переход не выполнен, `Authorization` на втором хосте не появляется, тело 3xx не читается, тело ответа ≤ cap+1.
- Источник: Fable (мой), проба подтверждена. Не блокирует закрытие A1: диф A1 этот код не трогал, A1 уязвимость не внёс.

### R2 — minor (hardening) · `_GistRawRedirect` копирует все заголовки исходного запроса
`common.py:469`: `headers=dict(req.header_items())` — при редиректе на тот же allow-list хост уйдут и `Authorization`/`Cookie`, если они были в исходном запросе. **Сегодня недостижимо:** `_raw` шлёт только `User-Agent` (`sync.py:114`; проба ContextVar показала заголовки `['User-Agent']`); `gh` ходит только на `api.github.com` (`_api_origin`, `sync.py:73–82`); авторизованный `_transport` ставит `follow_redirects=False` → `_NoRedirect` (`sync.py:63–64`; проба: 302 не следует); остальные вызовы `common.http` (`limits.py`, `update.py`) идут не на gist-хост. Цель редиректа ограничена `gist.githubusercontent.com` по TLS.
**Фикс (1 строка, A3):** в `http_error_302` отбрасывать `Authorization`/`Cookie`/`Proxy-Authorization` (или отказывать в редиректе при их наличии). **Тест:** прямой `common.http(gist_raw, headers={"Authorization": …})` + 302 на тот же хост → второй запрос без `Authorization`.

### R3 — minor · молчаливый пропуск файла при отклонённом редиректе / чужом `raw_url`
`sync.py:802–803`: `continue` без `lastError`; `sync.py:107–108`: чужой хост в `raw_url` от API → тот же `RAW_REDIRECT_REFUSED`. Владелец не видит, что файл не прочитан (Repudiation/visibility): MITM, смена инфраструктуры GitHub (новый raw-хост) или редирект на raw выглядят как «машин стало меньше»; `sync.py:845–846` затем стирают `lastError` и ставят успех. Решение — §6 (2). В текст ошибки **не включать `raw_url`** — его путь секретный (Astra).

### R4 — minor (hardening) · `tz` без предела длины
`sync.py:451`: `accounts._text(obj.get("tz"))` без `limit` → строка до 8 МиБ попадает в `sync-remote.json`; потребителей `tz` в `cli`/`gui` нет (grep). `name` тоже проверяется без предела, но обрезается до 16 (`sync.py:406–407`). ### R5 — info · кэш от версии до A1

### Проверено — угрозы нет
- **`ContextVar _raw_cap`:** не установлен → 8 МиБ (`sync.py:60`), не безлимит; установлен → `min` (`:62`, `:109`); сбрасывается в `finally`, в том числе при исключении транспорта (`:121`, проба); авторизованные запросы его игнорируют (`:61`); буферизующий транспорт ограничен `_bounded_response` (`:119`); новый поток значения не наследует (проба: `None`); вызовы синхронные, вложенных `_raw` нет. - **Тела ошибок** внутри и вне редиректов ≤ cap+1 (`common.py:508`; пробы 404 с бесконечным телом).
- **`cli.py` status/dump** — все пути печати чужих строк проходят `_machine_text`/`accounts._text`; `lastError`/`login` — не из gist-файлов.
- **Prompt-injection** — без изменений: из gist ничего не исполняется и агентам не попадает.

**(1) Второй рубеж N1 — перехват сбоя записи `sync-remote.json`: сейчас, узким перехватом; O1 — в A3.** По существу: `UnicodeEncodeError` из чужих данных больше недостижим — каждая строка выхода `merge`/`parse_block` проходит `_text`/`_label`/`_epoch`, A1-16 проверяет кодируемость всего выхода и чтение кэша строгим UTF-8; N1 этим не переоткрывается (Astra подтверждает). Остаётся локальный `OSError` (ENOSPC, EACCES, read-only FS): `write_atomic` (`common.py:63–85`) не оставляет полуфайла, но исключение выходит из `_sync_cycle` (`sync.py:844`) до формирования результата — трейсбек под таймером на каждом проходе, пока диск не починят. Моя первая оценка — A3 (семантика ошибок и O1); Astra — сейчас; серьёзность одинаковая (minor), беру строже. Тест — строка в §4. Если цикл правок уже закрыт — первым пунктом A3; не блокер.

**(2) Молчаливый пропуск vs видимая ошибка: видимая, как у большого файла.** Отклонённый редирект или чужой `raw_url` — аномалия транспорта (GitHub raw с sha не редиректит), MITM или смена инфраструктуры; молча терять файлы — значит прятать и атаку, и поломку.
