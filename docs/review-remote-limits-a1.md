## Блокирующее мерж (major)

### M1. `ccl-sync status` печатает в терминал сырые `machine.name/os/app` из свежего GET — П5-е не закрыт · источник: оба
- `linux/ccl/cli.py:268-283` (было до дифа, но П5-е прямо называет это место, а A1-14/T18 требует «ESC вычищены, ≤ 64»).
  Новый `_machine_text` (`sync.py:388`) применяется только в `sync.merge`; ветка свежего GET в `cmd_status` его обходит,
  а также не применяет предел 64 файлов.
- **Как показать:** фейковый `sync.gh` → gist с `machine-r.json` = `{"schema":1,"machine":{"id":"r","name":"\u001b[2Jattack","os":"x"*100,...}}`;
  `cli.cmd_status(None)` → в stdout есть ESC-последовательность и 100-символьный `os` (Sol воспроизвёл).
- **Фикс:** вынести `sync._machine_text` в общий хелпер (с фиксом M2) и прогонять через него `name/os/app` в `cmd_status`;
  перебирать файлы через `sync._machine_files`. Тест в A1-14 на путь `status`.

### M2. Одиночный суррогат (`"\ud800"`) в полях чужого файла роняет каждый цикл синка · источник: Opus
- Строки из JSON-escape `\ud800` проходят `_machine_text` (`sync.py:388-391`: категория `Cs`, не `Cc/Cf`), сырой `tz`
  (`sync.py:435`) и ключи корневых `days` (`p`/`d`/`model`, `sync.py:444-452`) → попадают в `remote` →
  `common.write_json(SYNC_REMOTE_PATH, remote)` (`sync.py:~810`) делает `.encode("utf-8")` → `UnicodeEncodeError` вне try.
  Цикл падает на каждом проходе у всех читателей, `lastOkAt` не двигается — ровно то, что T1/C7 запрещают.
  `accounts._text` эту проверку уже делает (`accounts.py:97-100`), а v1-поля — нет. Частично было до дифа (tz, ключи days),
  но `_machine_text` — новый код, заявленный как закрытие П5-е.
- **Как показать:**
  `sync.merge({"machine-x1.json": '{"schema":1,"machine":{"id":"x1","name":"\\ud800ab"},"updated":"<now>","tz":"\\ud800"}'}, "me")`
  → `json.dumps(r, ensure_ascii=False).encode("utf-8")` → `UnicodeEncodeError` (проверено).
- **Фикс:** `_machine_text` отбрасывает строку, если `value.encode("utf-8")` бросает (лучше переиспользовать
  `accounts._text`); то же для `tz`; в v1-цикле `merge` пропускать `p/d/model`, не кодируемые в UTF-8. Регресс-тест в A1-13/A1-14.

## Ответы по решениям Юрки

- **R1 — соответствует.** `_fail` после `st.update(lastOkAt=…, backoffUntil=None)` → `backoffUntil` не ставится, `_rate_limited` не
  трогается. `warning()` (`sync.py:828`) не ломается: `lastErrorAt ≈ lastOkAt`, условие `error_at > since + STALE_AFTER` ложно →
  оранжевой строки нет (ошибка видна в настройках GUI `app.py:662` и в `ccl-sync status` как «Last error»). Следующий
  полный проход стирает `lastError`. Побочка — m4 (CLI код 1, контракт для A2).
- **R2 — соответствует.** `_machine_text`: `name[:16]`, `os/app` > 64 → `""`, `Cc/Cf` → строка целиком отброшена. Дыра —
  суррогаты (M2) и путь `status` (M1).
- **R3 — соответствует по смыслу,** 8 = после валидации и дедупа; новые версии уже взятых ключей учитываются. O(n²) нет
  (dict по ключу), но объём сырой работы не ограничен → m1.

## Ответы по пунктам 1–8

1. `_machine_files` до исключения своего файла (`sync.py:372, 768`) — **ок** (буква протокола: «первые 64 по имени»).
   Долг: зафиксировать в протоколе «свой файл занимает слот», чтобы macOS-порт (C1) сделал так же.
2. `build` → `ValueError` — **долг** (m5).
3. `lastSeenAt` числом — **ок** (шапка `test_rl_contract.py:13`, единообразно с `machine.updated`, который тоже epoch);
   на проводе ISO не затрагивается. Nit n5.
4. Схлопывание `label: null` одного продукта — **ок**: протокол дедупит по `(product, label)`, `null` — тоже ключ; писатель и так
   выпускает ≤ 1 `null` на продукт, а дни отброшенного дубля приводят к расхождению проекции → корень в «не указан», без
   двойного счёта. `stale` у читателя — зарезервированный, но известный статус → **ок**; писатель меняет на `error` — **ок**
   (v1.1-писатели его не ставят).
5. Редиректы — **долг, minor** (m3): реальный риск низкий, фикс дешёвый.
6. `read_local_id` на каждом проходе — по протоколу («Re-read on every pass»); нагрузка — одно чтение ≤ 8 МБ + `json.loads`
   на продукт за скан, приемлемо. Извлекаются только `oauthAccount.accountUuid` / `tokens.account_id`; наружу (возврат,
   индекс, логи, исключения) другие поля не уходят. `localId` попадает только в `usage-index.json` (0600) — так требует П1-б.
   `organizationUuid` не используется. **Ок**, nit n1/n2.
7. `FileNotFoundError` → сразу `no_login` — **ок.** Ретраи на частичную запись (`ValueError`) сохранены; замена через
   `rename` окна «файла нет» не создаёт. Ретраи на ENOENT вредны: `product_enabled` по умолчанию `True`, и машина без Codex
   спала бы 0,8 с на каждом скане. Цена редкого промаха — один день `null` (уходит в «не указан», без потерь суммы).
8. `accountByDay` — **ок** по протоколу v1.1 (день целиком за первым владельцем, не меняется; очистка вместе с 45-дневной
   историей в `prune`; день, который уже был в индексе до A1, не атрибутируется). Смена входа посреди дня (A6): остаток дня
   идёт под старой меткой, новая получает расход со следующего дня — PRD это допускает («приблизительна», «до цикла
   индексации»). Nit n4.

## Security

Проблемы: M1 (управляющие последовательности в терминал), M2 (DoS чтения одним файлом), m1–m3 (пределы читателя).
Секреты в код/логи не попадают; метка и чтение `localId` по протоколу.

**Security surface: да** — парсинг недоверенного входа (чужие файлы gist), чтение локальных файлов входа с секретами
(`~/.claude.json`, `~/.codex/auth.json`), сетевые пределы тел ответов. → T2: `security-analyst` до мержа.

**Вердикт:** нужен ≥ 1 цикл правок (M1, M2; желательно m1–m2 в том же цикле).
