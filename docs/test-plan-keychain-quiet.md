## Уровни доказательств и изоляция

- **P — pure/fake:** реальные точки входа будущего frozen patch с инъекциями; никаких Security.framework/Keychain, app startup, CLI, API, userlogs. Память/свои tmp, синтетические секреты, фиксированные wall/monotonic clocks, управляемые scheduler/completions. Все достижимые network/store/process/defaults/log/CLI-home эффекты заранее заменены фейками или запрещающими заглушками, включая конструкторы и callbacks. Ветка «обычно not-due» не защищает изоляцию. Неимитированный эффект немедленно FAIL; зависшие фейки освобождаются при завершении теста.
- **N — native isolated, требуется отдельно:** поведение реального macOS backend и системного окна нельзя доказать фейком. Только после отдельного назначения координатора, ревью harness и заморозки patch: отдельная disposable VM/учётная среда без пользовательских credentials, синтетические записи в отдельном хранилище, запрет сети, контроль реально используемого хранилища/identity и системных окон. Одного нового service name или HOME/tmp недостаточно. В этой задаче N не запускается.
- **Запрещено live:** установленное приложение, login Keychain/реальные ACL, `/usr/bin/security` даже read-only, реальные API/gist, CLI, credentials и пользовательские журналы. Не выполнять lock/unlock/delete реальной связки и не читать её для «проверки изоляции». Сборка, app/selftest/CLI/runtime-запуски в текущую задачу не входят.

## Матрица регрессий и AC

Фейк умеет требовать разрешение на любую операцию; recording spy фиксирует фактические boundary-вызовы, контекст действия и политику взаимодействия. Варианты ответа: success, достоверный missing, interaction-required/locked/unavailable, deny/cancel, timeout/hang, late success. Проверять наблюдаемые результаты и целостность данных, не воспроизводить production алгоритм в oracle.

Проверку native minimum macOS13 и текущей целевой ОС фиксировать раздельно; compile/packaged validation сами не доказывают Q1.

## Seam, необходимый от developer до независимых тестов

1. Безопасный headless вход в настоящие store/sync/recovery операции; injectable boundary backend для read/stage/readback/delete/legacy/enumeration/GC. Spy видит окончательную политику UI у каждого backend-вызова, action context и generation, включая внутренние вызовы. Тест отдельного enum/formatter недостаточен.
2. Injectable clocks/scheduler, transport, subprocess runner и storage/defaults/log sinks; управляемые timeout/late completions и барьеры публикации. Тестовый путь не создаёт обычный AppDelegate и не может уйти в native fallback.
3. Synthetic metadata snapshot/restore для restart, наблюдаемые active ref/epoch/tombstone/pending cleanup; срок D и точная граница интерактивного действия (операции, окончание, cancel) как контракт. Никаких секретов в trace.
4. Developer передаёт координатору frozen diff/ревизию и seam; координатор отдельно назначает тестовые файлы Tester. До этого Sources/тесты автора не меняются, независимые регрессии не запускаются. Если seam отсутствует, соответствующая проверка остаётся «не выполнена».

## Ожидаемые false PASS и отчёт после continuation

- «600 seconds passed», сброшенный gate или одна успешная retry ≠ отсутствие UI; restart, Always Allow, соседняя запись и GC могут обойти такой тест.
- Zero calls при not-due/заблокированном scheduler ≠ безопасная boundary-политика. Для каждого Q1 нужны свидетельство достигнутого пути и реальные captured параметры; отдельно учитывать сознательно подавленные операции.
- Fake backend «никогда не рисует окно» ≠ native no-UI. Проверка только root read и текстовый поиск флага ≠ покрытие вложенных stage/readback/legacy/delete.
- Success/counter/compile/bitmap/код 0 ≠ изоляция или отсутствие prompt; skip и непроверенные native ACL не считаются PASS. Реальные часы и tmp service не изолируют эффекты (006/011).
- Параметры правильны у spy, но native adapter их игнорирует; deny ошибочно возвращает missing; поздний success публикует после logout — отдельные риски, не закрываемые общим числом passed.

После frozen patch: для каждого Q-ID указать выполненный уровень P/N, фактическую команду, результат/skip, exact Git HEAD и fingerprint незакоммиченного дифа. Для найденной регрессии по возможности показать FAIL baseline и PASS candidate на одинаковом изолированном сценарии; это сейчас не выполнено. Изменение файлов после прогона явно аннулирует применимость результата к новому дифу. Общую приёмку сводит координатор; native/packaged/live ограничения перечисляются явно.
