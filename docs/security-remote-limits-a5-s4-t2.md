## 4. Обход на старом коде `6aae7a6`

Команда: `env -u DBUS_SESSION_BUS_ADDRESS -u DISPLAY XDG_RUNTIME_DIR=/run/user/<uid> ccl-sync login --no-browser`.

**Даёт ли файл.**
- `login_backend` и `store` выбирают файл, если SS отсутствует или коллекция по умолчанию заперта.
- Без `DBUS_SESSION_BUS_ADDRESS` libdbus идёт в `$XDG_RUNTIME_DIR/bus`. Это шина таймера, а таймер видел keyring запертым. Значит, на практике получится файл.
- **Гарантии нет** (Sol, согласен): если keyring на этой шине разблокирован, токен снова уйдёт в SS.
- Как проверить: строка «Готово… (токен в файле …)». Старый код печатает путь `github-token` даже для V2-файла — это косметика, важно слово «файле». Если там «хранилище секретов» — остановиться.

**Риски.**
- Prompt не появится: `Unlock` возвращает prompt, его никто не исполняет; `DISPLAY` нет; `--no-browser` не запускает `xdg-open`.
- Токена нет ни в argv, ни в окружении, ни в выводе. Печатается только `user_code` Device Flow.
- Повторять обход не нужно: на `6613d18` вход издателя пишет файл независимо от keyring.

## 5. Владельцу после установки `6613d18`, если старый токен в SS

1. `ccl-sync status`. Ожидается подсказка «токен в хранилище секретов… logout, затем login». Таймер в это время стоит и SS не читает.
2. В терминале XFCE (keyring разблокирован) — `ccl-sync logout`. Строки «Выход не завершён» быть не должно; если она есть — повторить там же. Из SSH logout не делать: удаление не пройдёт (m7).
3. Необязательно, для полной чистоты: отозвать авторизацию приложения на github.com/settings/applications **до** шага 4. Это убивает все его токены, в том числе старый refresh.
4. `ccl-sync login --no-browser` — откуда угодно.
5. `ccl-sync status`: «GitHub: <login> (токен: …/github-credentials/…)», без «Выход не завершён».
6. **Не делать** `login` без шага 2 из SSH: старая копия останется в SS молча (M3).

`secret-tool search` для проверки не использовать: он печатает секрет.
