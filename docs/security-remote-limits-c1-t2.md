## 2. Что закрыто (проверено по коду)

- **raw только `https://gist.githubusercontent.com/`.** `syncRawURL` (`LimitsMonitor.swift:1458-1466`) проверяет буквальный префикс со слешем, печатный ASCII, `host`/`percentEncodedHost`, отсутствие userinfo, порта и fragment. Проверка выполняется на значении из API, на каждом переходе (`:2246`, `:2254`) и ещё раз в `syncHTTP` (`:1447`). Обходы перебрал: регистр, `@`, `:443`, завершающая точка, `\`, `//evil`, `https:evil`, percent-host, относительные Location — смены хоста нет. Sol пришёл к тому же.
- **Редиректы.** Не больше 3 переходов (4 запроса, `:2245-2257`). Принимаются только 301/302/303/307/308; 300/304/305 и Location без допустимого URL дают отказ. Тело 3xx не читается: `.cancel` в `didReceive response` (`:117`), автопереход URLSession выключен (`:107-109`).
- **Authorization/Cookie.** На raw уходит только `User-Agent` (`:2248`). Сессия ephemeral, `httpShouldSetCookies=false`, cookie storage и credential storage — `nil` (`:132-135`). Авторизованный GET (`api.github.com`) тоже не следует редиректам, поэтому Bearer не покидает хост. Служебный заголовок `X-CCL-Body-Limit` срезается до отправки (`:1452`) и может только уменьшить предел.
- **Пределы тела.** Делегат хранит не больше cap+1 байт при любом Content-Length (`:119-123`). Задержка ожидания ограничена: 20 с простоя плюс 5 с (`:141`). GET API — 16 МиБ (`:2236-2238`), raw — 8 МиБ. Бюджет 64 МиБ считается по проводу, отвергнутое тело учитывается как cap+1 (`:2847-2858`). Не больше 64 файлов, свой файл занимает слот (`:2826-2834`). Отказ raw или превышение пропускает файл, а не цикл. Свой PATCH идёт до чтения чужих файлов (`:2813-2820`) и от них не зависит.
- **`syncRejectedRaw` (UserDefaults).** Ключ — 16 hex от SHA256(URL), значение — время. Ни URL, ни gist id, ни sha ревизии там нет. Срок 24 ч, записи с будущим временем отбрасываются, не больше 64, вытесняется самая старая (`:2260-2282`). Состав совпадает с Linux `_raw_key`.
- **C7 / П4-в / П5-е (читатель).** Cc/Cf отвергаются целиком (`RemoteLimits.swift:132-146`); подписи ≤ 32 NFC, модели ≤ 48 NFC, `plan`/`tier`/`os` ≤ 64, имя машины проверяется и обрезается до 16 (`:334`), при отказе ставится «?». `pct` — конечное число в 0…100 без CFBoolean. Целые — без `f`/`d` и с пределом до `intValue`, `legacyInteger` — точное приведение `as? Int`, ловушек переполнения нет. Суммы проекции ≤ 9·10¹⁵ (`exactAdd`), остальное сложение насыщающее (`usageSum`). Ключи `days` проверяются. Одиночный суррогат не может стать `Unicode.Scalar`; селфтест требует, чтобы не было и U+FFFD (`RemoteLimitsSelfTests.swift:398`). Чужие строки не попадают в `String(format:)` и не трактуются как HTML: отрисовка идёт через NSAttributedString/CTLine (`LimitsMonitor.swift:5253-5262`). Для пиров v1.0 это улучшение: раньше `m["name"]` попадал в UI без очистки и без предела длины.
- **Т36.** `date()` (`RemoteLimits.swift:178-212`) принимает строку ≤ 4096 байт с якорным regex: год из 4 цифр, смещение < 24 ч, `24:00` и `:60` отвергаются, в `[0-9]` только ASCII. Год 99999, `+99:00` и дробь из 10⁶ знаков отбрасывают поле. Свой разборщик, без `DateFormatter`, — Foundation ничего не нормализует.
- **N10 (значения).** Будущий `asOf > now+300` проигрывает и нормальному локальному, и нормальному чужому снимку, при равенстве побеждает локальный (`:426-445`). Статус `latest` выбирается по нормальным `attemptAt ?? asOf` (`:447-453`).
- **Метка HMAC.** Ключ — SHA256(`"ccl-label-key-v1|"+gistId`) в сыром виде, без trim, как в Python. Сообщение — `"ccl-account-v1|"+product+"|"+strip.lower(id)`, берутся первые 8 байт (16 hex). Совпадает с `accounts.py:28-31`; форма id `[0-9a-z-]{8,64}` — как N12. `localId` наружу не уходит. `historyKey` — локальный отпечаток без ключа, в gist в C1 не уходит (§3, S9).

## 6. Живые пробы на маке после сборки (remote-hands, синтетика, изолированные defaults и каталог, не боевой gist)

1. `bash build.sh && "$APP" --sync-selftest` — exit 0. Записать, какая ветка C1-02(a) сработала: «файл слит, окна отброшены» или «файл отвергнут целиком».

3. NSJSONSerialization на Darwin: какой из дублирующихся ключей побеждает (у Python — последний), `1e400`, целое из 10⁵ цифр, `\ud800` (весь файл отвергнут или U+FFFD), типы NSNumber для `1`, `1.0`, `1e15`, около Int64.
4. Транспорт против локального сервера: бесконечное тело без Content-Length и с заниженным Content-Length → хранится ≤ cap+1, ошибка «exceeds body limit»; gzip/br-бомба → ≤ cap+1, RSS ограничен; 302 с бесконечным телом → статус 302, тело не принято; капельная отдача → возврат ≤ 25 с; 1000 таймаутов подряд → нет роста потоков, fd и RSS.
5. Заголовки на каждом переходе raw (лог сервера): только `User-Agent`, нет `Authorization`, `Cookie`, `X-CCL-Body-Limit`. `Set-Cookie` первого ответа на втором переходе не возвращается.
6. Пиковая память полного цикла (`/usr/bin/time -l`): 9 × 7,5 МиБ raw плюс 54 мелких файла — Т30 «память ≤ предел». При большом пике обернуть разбор каждого файла в `autoreleasepool`.
7. `stat -f '%Sp' ~ ~/.claude-limits-monitor ~/.claude-limits-monitor/sync-remote.json` — права. Наличие gist id в файле проверять только счётчиком (`grep -c`), значение не печатать. После фикса S2 — 0.
8. Тестовый gist (не боевой): `git push` бинарного `machine-test.json` на 2 МиБ. До фикса воспроизводится S1 (чтение прерывается каждый цикл). После фикса остальные машины слиты, ошибка видна, `syncLastOkAt` двигается.
9. Карточка «Синхронизация» в настройках: имена с U+2028, U+3164, PUA, 15 комбинирующими знаками → нет вылезания в соседние строки (скриншот).
