# MANUAL-REFRESH — предложение сценария

2026-10-07. Статус: предложение по запросу пользователя; реализация не поручена. Проверенная база:331c1f7. Изменений production нет.

## Наблюдаемая причина

В macOS кнопка вызывает doRefresh(live:true), но AutoPollState.due ограничивает ручной запрос минимумом900с, а при failed — полным interval. При fetchingLimits или пустом наборе допущенных продуктов doRefresh молча возвращается. Ручное действие не имеет явного результата для пользователя.

## Предложение

- В шапке доступная кнопка «Обновить сейчас» со значком обновления. Она запрашивает свежие остатки включённых сервисов, независимо от выбранной частоты автообновления и локальной паузы после сетевой ошибки.
- Сразу показать «Обновляем…», сохранить прошлые значения до ответа. Не создавать дубликат запроса повторными нажатиями. Короткая защита от частых повторов одинакова в Auto и фиксированном режиме; предварительное UX-предложение —30с с видимым обратным отсчётом, требует реализации/проверки.
- Результат отдельный для Codex и Claude: «Проверено только что», «Не удалось связаться; данные на22:10», либо конкретное действие восстановления входа. Одинаковые проценты после успешного ответа — успешное обновление, не ошибка. При fallback на старый снимок не обновлять время получения данных.
- После частичной ошибки доступен повтор только проблемного сервиса. Новый успешный результат одного сервиса показывается сразу, не ждёт второго.
- Реальный серверный запрет повторного запроса не обходить. Если сервер передал срок, показать «Сервис разрешит повтор через…» и назначить попытку на разрешённое время. Не выдавать локальную паузу за ограничение сервера; при неизвестном сроке не выдумывать его.
- Показывать раздельно время последнего успешного получения и следующей автоматической попытки. Не переключать выбранный пользователем режим расписания после ручного запроса; учитывать выполненный запрос, чтобы таймер не отправил немедленный дубликат.
- При проблеме входа показывать «Восстановить доступ» с адресным следующим шагом. Не запускать повторный вход и системные разрешения автоматически при нажатии обычного обновления.

## Критерии следующего шага

Ручная попытка до истечения900с; ручная попытка после локальной сетевой ошибки; реальный Retry-After; двойное нажатие/in-flight; частичный успех; unchanged fresh answer; fallback со старым asOf; auth action; RU/EN и оба режима расписания. Изолированные проверки без реальных credentials/API. Это план проверок, не выполненные тесты.
