## 2026-10-31 — C5: принятые F1/F2/F3/F5/F7/F8 независимого review fix4

1. По прямому брифу владельца C5-12 проверяет NSApp activation из inactive baseline и доставку клавиатуры/кликов через NSApp.sendEvent, а не вызовы методов field editor/handler. Local/global monitor tokens обязательны; счётчик в реальном local callback доказывает доставку. Локальная агрегация ошибок fix5 сохраняется, политика не ослабляется.
2. Возврат фокуса — прежнему frontmost приложению, захваченному до активации; если оно отсутствует/завершено/запрос отклонён — deactivate. Уже выбранное пользователем внешнее приложение не перехватываем. Generation отменяет отложенный возврат при новой правке и сохраняет previous app при переключении карандашей. Безусловное перепоказывание панели отменено; ordering остаётся запасным публичным путём только для ещё-key панели после150мс, поскольку Apple запрещает прямой resignKey.
3. Клики по counter/error и тому же карандашу сохраняют editor/draft; другие клики отменяют по прежнему правилу. Неверный оконный host отвергается до создания editor (assertionFailure в debug), без тихого makeFirstResponder fallback. Panel тестового контроллера явно isReleasedWhenClosed=false. Прогон WindowServer требуется; Python/внутренних агентов/собственного ревью/Git-мутаций нет.

## 2026-10-31 — C5 / 3.3.1: подписи и долги C4 (рабочий патч)

## 2026-10-12 — REMOTE-LIMITS: «только чтение» токенов на всех портах; gist не пересоздаём

(2) Замер: GitHub отдаёт только 30 последних ревизий — старые имена вытеснятся сами, пересоздание сломало бы настройку на всех машинах.

## 2026-10-15 — REMOTE-LIMITS A3: уточнения к тестам (решение Юрки, технические)

## 2026-10-15 — REMOTE-LIMITS A3: поправки к §D по шагу 1 (решение Юрки)

1. Цепочка чужих дедлайнов: если между двумя принятыми чужими `retryUntil` своего опроса не было, `firstSeenAt` наследуется, и вся цепочка ограничена 24 ч. ## 2026-10-15 — REMOTE-LIMITS A3: обрыв цепочки чужих дедлайнов, A1-14 vs N8 (решение Юрки)

1. Цепочка чужих `retryUntil` наследует `firstSeenAt`, только если новый срок принят, пока прошлый `effective` ещё действует или истёк ≤ 900 с назад. Иначе — новая цепочка, `firstSeenAt = now`. 2. Крайний случай «обычный срок кончился ровно на потолке, приходит новый чужой срок»: событие `remote_retry_capped` не пишется, опрос есть — принимается как есть.
