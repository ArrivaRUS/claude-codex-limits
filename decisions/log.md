# Журнал решений — claude-codex-limits

> Что решили и ПОЧЕМУ. Новые записи сверху. Заведён 2026-09-29 (раньше решения жили в коммитах и README).

## 2026-10-03 — Юрка автоматически, исполнение только Codex
- **Решение владельца:** подключённая вместе с проектом папка Юрки означает обязательное разделение ролей, проектный план, бэклог, гайд и записи в Git. Этот проект переведён в такой режим; отдельная команда не требуется.
- **Уточнение владельца:** использовать только Codex. Claude Code и другие движки не запускать. Роли исполняются отдельными субагентами Codex по HQ `handoff/references/codex-only.md`; исторические model-поля Claude-уставов в этом режиме не применяются.
- **Факт:** релизы macOS3.2.0/Linux0.4.0 на `e6e2f2e` были подготовлены одним агентом. Успешные тесты не заменяют независимых архитектурных/кодовых/ИБ-проверок. Долг фиксируется в бэклоге, не закрывается ретроспективным описанием.

## 2026-10-03 — оформление кнопки Auto и видимая частота
- **Решение владельца:** сделать «А» стилизованной; при включении Auto рядом рисовать текущую частоту обновления. Не обозначать её обводкой ручного тайм-слота.
- **Граница:** алгоритм Auto, стандартные интервалы и сетевое поведение сохраняются. При двух подписках разные интервалы отображать с понятными названиями продуктов; текст берётся из действующих состояний расписания.
- Требования текущей UI-правки приняты прямым запросом. Цвета, геометрия и размещение — UX-спецификация, без нового выбора направлений. По умолчанию фиксированные 30 минут остаются.

## 2026-09-30 — выкладка Linux = релиз `linux-v…`, не merge (Linux-сторона)
- **Решение человека:** «опубликуй» — релиз `linux-v0.3.2` (.deb, не Latest) опубликован 11:34Z Linux-стороной; «сам скажи проекту на Маке, сделай запись в гите» — эта запись, HEARTBEAT и урок 009.
- **Поправка к записи ниже:** «Merge в `main` = выкладка Linux» неверно для пакета .deb: трей предлагает обновление только по релизу `linux-v<версия>` с `*_all.deb` (`linux/ccl/update.py`, `is_packaged()`). Из `main` обновляется только старая установка `linux/install.sh`.
- **Почему так:** пакет ставится в `/usr` через dpkg с паролем; скачивать исходники из `main` поверх него нельзя. Релиз всегда `--latest=false` — `releases/latest` читают обновлятор Мака и `get.sh`.

## 2026-09-30 — «да» на push и merge заранее, с условием
- **Решение человека:** «Да, даю да заранее» на push ветки `fix/sync-401-silent-revoke` и merge в `main` — при условии, что финальные ревью корневого фикса Ctrl+C (code-reviewer + ИБ T2/T3) без blocker/major. Иначе — стоп и вопрос.
- Merge в `main` = выкладка Linux (трей предложит «Обновить»). GitHub-релиз macOS 3.1.3 (DMG) этим «да» НЕ покрыт — отдельный вопрос.

## 2026-09-30 — Ctrl+C при записи токена: лечить корень
- **Решение человека:** «Лечить корень сейчас» (рекомендация Юрки).
- **Контекст:** третье микросекундное окно одного класса (Ctrl+C в `vault._timed`: ожидание → старт потока (F-1) → ветка таймаута, плюс двойное прерывание). Правило «один баг > 2 раз = долг процесса»: окна по одному больше не латаем.
- **Что:** на время записи токена в хранилище (до 15 с) SIGINT откладывается и срабатывает сразу после критической секции — закрывает все окна, включая двойное нажатие. Не брать вариант Astra «не снимать SS-ссылку в `finally`» — на машине без SS даёт вечное «Выход не завершён».

## 2026-09-30 — F-1 и F-2 чиним до релиза
- **Решение человека:** «Чинить F-1 и F-2 сейчас» (рекомендация Юрки).
- **F-1:** `t.start()` в `vault._timed` вне `try` — Ctrl+C в микросекундном окне оставляет неотслеживаемую копию токена (Astra: blocker, ИБ: major). **F-2:** временник `write_atomic` после SIGKILL живёт до выхода — `_file_delete(gen)` должен удалять и его.
- В тикет после релиза: F-3, L-4 (+ путь через файловый fallback), ниты; m-1, m-2, m-4, m-5, n-1…n-4 код-ревью.

## 2026-09-30 — четвёртая (сверхлимитная) правка: «исправить сейчас»
- **Решение человека:** «исправить сейчас» — две находки tester после цикла 3 чиним до релиза, а не следующим релизом.
- **Что:** (1) Linux без Secret Service: вечное «Выход не завершён» — `_delete_stored` считает «SS нет» неудачей для `("legacy", None)`; (2) Ctrl+C во время зависшей записи в KWallet оставляет неотслеживаемую копию — `_timed` не ставит `abandoned` на `BaseException`.
- **Почему сверх лимита 3 циклов:** лимит исчерпан, продление — только с «да» человека; первая находка видна пользователю, а merge = автообновление Linux.
- Код выхода `cmd_push` для «нет D-Bus» остаётся 3 (старый контракт; решение Юрки).

## 2026-09-30 — отзыв токена на GitHub при выходе: нет
- **Решение человека:** «Нет, как сейчас». `POST /credentials/revoke` не используем; выход только локальный.
- **Юрка рекомендовал «да»** (не копятся слоты лимита 10, нет каскада отзывов); человек выбрал отсутствие писем GitHub на каждый выход.
- **Следствие:** остаточный риск сожжённых слотов при частых выход/вход принят; в UI выхода подсказка про github.com/settings/applications (из «варианта а») остаётся.

## 2026-09-30 — объём захода правок (Юрка)
- **Решение:** в один заход правок `developer-codex` (Astra @high) берём находки всех пяти ревью обеих платформ, включая унаследованные A2/D5 (крэш от чисел чужой машины), A1 (только secret-гист), A3, A4. Linux-хранилище чиним поколениями элементов Secret Service, keyring не убираем.
- **Почему:** A2/D5 — major по устойчивости, фикс маленький, в релиз T3 без него не пустили бы; второй заход ради них — лишний цикл ревью. Вариант «только файл 0600» — продуктовое изменение, поколения закрывают векторы A/B/C без смены UX.
- **Открыто у человека:** отзыв токена на GitHub при выходе (`POST /credentials/revoke`, письмо владельцу на каждый отзыв).

## 2026-09-30 — политика отзыва входа: вариант «а»
- **Решение человека:** «вариант а» (выбор между «а» перепроверять ещё раз и «б» не удалять токен вовсе; Юрка рекомендовал «б»).
- **Что делаем:** при 401 на гист → `GET /user`; если снова 401 → пауза 3–5 с и **ещё одна** проверка `GET /user`; только третий подряд 401 = настоящий отзыв: флаг `syncRevoked`, токен удаляется из хранилища, если там тот же. Обе платформы, контракт `docs/sync-protocol.md`.
- **Почему:** отсеять случайные сбои GitHub, не усложняя интерфейс. Остаточный риск принят: при настоящем отзыве и перевходе на GitHub копятся живые токены (серверного revoke у device flow нет) — лимит 10 на пользователя/приложение/scope. Подсказку в UI выхода «отзыв — на github.com/settings/applications» добавляем как дешёвую страховку.

## 2026-09-29 — чиним тихий отзыв входа в синхронизации
- **Решение человека:** «чиним» после диагноза debugger (обе машины молча перестали синхронизировать гист после одного ответа 401).
- **Что меняем:** отзыв входа только после подтверждения `GET /user` = 401; чтение гиста каждый цикл независимо от локальных изменений; состояние синхронизации видно на основном экране.
- **Почему:** одна ошибка сети или авторизации не должна молча выключать функцию на сутки; пользователь видел неверные суммы ($1 и $41 вместо ~$42) и не знал об этом.
