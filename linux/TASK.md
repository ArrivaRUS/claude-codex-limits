# ТЗ: Claude Codex Limits для Astra Linux Special Edition

Задание для сессии Claude Code, запущенной на компьютере с Astra Linux SE. Исходная
macOS‑версия лежит в этом же репозитории: `Sources/LimitsMonitor.swift` — это эталон поведения,
форматов и формул. Здесь надо сделать Linux‑порт в каталоге `linux/`.

Зачем это нужно: владелец работает под одной учёткой Claude и Codex на двух компьютерах — Mac и
Astra Linux. Проценты лимитов сервер отдаёт на всю учётку, а расход по дням и моделям (столбики,
календарь, деньги в расширенном режиме) есть только в локальных логах той машины, где работал CLI.
Поэтому расход с Astra сейчас не виден нигде.

## Порядок работ

Делать по этапам. Каждый этап — рабочий результат, который можно проверить и закоммитить.

### Этап 1. Сборщик расхода + синхронизация через GitHub (главное)

Консольная утилита `linux/ccl-sync` (одна команда, без GUI), которая:

1. Индексирует локальные логи Claude Code и Codex на этой машине — **точно по**
   [`docs/sync-protocol.md`](../docs/sync-protocol.md), раздел «One file per machine».
   Эталон разбора — `UsageLogs.scan` / `scanFile` в `Sources/LimitsMonitor.swift`:
   - Claude: `~/.claude/projects/**.jsonl` **включая** `<session>/subagents/agent-*.jsonl`;
     дедупликация одного `message.id` в пределах дня (сообщения повторяются после resume и
     компактификации).
   - Codex: `~/.codex/sessions/**/rollout-*.jsonl`, события `token_count`,
     `input = input_tokens − cached_input_tokens`, модель из последнего `turn_context`.
   - Инкрементально: помнить размер файла и дочитывать только новые полные строки. Логи бывают
     гигабайтами — полный разбор каждый раз недопустим.
2. Входит в GitHub через Device Flow (`ccl-sync login`: печатает код и ссылку, ждёт подтверждения),
   хранит токен (Secret Service, если есть; иначе файл `0600` в `~/.config/claude-codex-limits/`).
3. Находит или создаёт секретный gist и пишет туда `machine-<id>.json` — строго по протоколу.
4. Команды: `ccl-sync login`, `ccl-sync logout`, `ccl-sync status` (кто вошёл, gist, какие
   машины есть в gist и когда обновлялись), `ccl-sync push` (один проход), `ccl-sync dump`
   (сводка по дням и моделям локально, для проверки цифр — аналог `--advanced-dump` на Mac).
5. Автозапуск раз в 10 минут: systemd user timer (`~/.config/systemd/user/`), если в системе
   доступен `systemctl --user`; иначе cron. Инструкция установки — в `linux/README.md`.

Критерий готовности этапа 1: после `login` и `push` в gist появился файл этой машины; `dump`
показывает за последние дни модели и токены, которые сходятся с логами (сверить вручную на паре
дней, как сверялся Mac: число ходов ±3). Mac‑версия (её синхронизацию делают параллельно на Mac)
видит этот файл.

### Этап 2. Значок в трее с лимитами (простой вид)

Приложение в системном трее Fly: два числа как на Mac (по умолчанию 5‑часовая сессия Claude и
неделя), по клику — панель с карточками Claude Code и Codex: проценты, время сброса, цвет по
уровню (до 50% / 50–79% / от 80%). Источники данных — как на Mac:

- Claude: `GET https://api.anthropic.com/api/oauth/usage` с токеном из
  `~/.claude/.credentials.json` (на Linux Claude Code хранит учётные данные там, структура та же:
  `claudeAiOauth.accessToken/refreshToken/expiresAt`). Обновление токена, заголовки,
  `limits[]` для недельных лимитов по модели, обработка протухшего входа — см. `fetchClaude()`.
- Codex: `GET https://chatgpt.com/backend-api/wham/usage` с токеном из `~/.codex/auth.json`,
  см. `codexUsageLive()` / `codexApplyWindow()`. 5‑часового окна у Codex больше нет — строку
  сессии показывать, только если сервер её вернул.

**Критично про токены Claude.** Refresh‑токен одноразовый (ротируется). Если утилита обновила
токен, она **обязана** атомарно записать новые `accessToken`/`refreshToken`/`expiresAt` обратно в
`~/.claude/.credentials.json` (временный файл + rename, права `0600`, остальные поля сохранить),
иначе Claude Code на этой машине разлогинится. Лучше вообще не обновлять токен, пока он живой, —
как на Mac (обновление только если до истечения меньше 2 минут). Отказанный refresh‑токен
(`invalid_grant`) повторно не слать — см. `deadRefresh` в исходнике.

### Этап 3. Расширенный вид

Паритет с расширенным режимом Mac: темп по каждому окну (`windowPace`), столбики за 7 дней по
моделям в $ по API‑прайсу (`MODEL_PRICES`, `apiCost`), календарь за 35 дней, деньги по подписке и
по API. Данные расхода — сумма локального индекса и файлов других машин из gist.

## Ограничения среды Astra Linux SE

- Базовая версия ОС: узнать `cat /etc/astra_version` и сообщить в issue. Писать под
  **Python 3 из репозитория ОС** (в 1.7 это 3.7, в 1.8 — 3.11) — только стандартная библиотека,
  HTTP через `urllib`. Для GUI — **PyQt5 из репозитория** (`python3-pyqt5`), `QSystemTrayIcon`.
  Никаких `pip install` из интернета: в закрытом контуре их может не быть.
- Замкнутая программная среда (ЗПС) и контроль интерпретаторов могут запрещать запуск
  неподписанных бинарников и скриптов. Сначала проверить (`astra-digsig-control`,
  `astra-interpreters-lock` — статус), и если что‑то блокируется — остановиться и описать
  владельцу, какие варианты есть (подпись, исключение, запуск через системный интерпретатор).
  Не отключать защитные механизмы самостоятельно.
- Мандатный контроль целостности: всё хранить в домашнем каталоге пользователя, никаких
  системных путей и `sudo`.
- Автозапуск GUI — `~/.config/autostart/claude-codex-limits.desktop`.

## Правила

- Работать в ветке `astra-linux`, результат — pull request в `main`. На Mac параллельно идёт
  работа в `main` (синхронизация на стороне macOS), конфликтов быть не должно, пока порт живёт
  в `linux/`.
- **Никогда не коммитить секреты**: токены, `auth.json`, `.credentials.json`, кэши, индексы, gist
  id. Перед каждым push проверять:
  `git ls-files | grep -iE "token|auth\.json|credentials|cache|index\.json|machine-id|\.local\."`
  — вывод должен быть пустым.
- Токены никогда не печатать в терминал и логи, даже частично.
- Протокол синхронизации — общий контракт с Mac. Если его нужно изменить, не менять молча:
  описать предложение в issue.
- `GITHUB_CLIENT_ID` брать из `docs/sync-protocol.md` (раздел Client ID).

## С чего начать

1. Прочитать `docs/sync-protocol.md` целиком и функции `UsageLogs`, `fetchClaude`,
   `codexUsageLive`, `windowPace`, `MODEL_PRICES` в `Sources/LimitsMonitor.swift`.
2. Проверить среду: версия Astra, Python, PyQt5, ЗПС, есть ли `~/.claude/projects` и
   `~/.codex/sessions` и сколько там данных.
3. Показать владельцу план этапа 1 и после его «да» делать.
