# Claude Codex Limits для Astra Linux

Linux-порт macOS-приложения из этого репозитория. Эталоном поведения, форматов и формул служит
[`Sources/LimitsMonitor.swift`](../Sources/LimitsMonitor.swift), а общим контрактом с Mac —
[`docs/sync-protocol.md`](../docs/sync-protocol.md).

Порт состоит из двух частей:

| | что делает | нужно |
|---|---|---|
| **`ccl-sync`** | индексирует локальные логи Claude Code и Codex и пишет расход этой машины в ваш секретный gist, откуда его видит Mac (и наоборот) | Python 3 из репозитория ОС, только стандартная библиотека |
| **`claude-codex-limits`** | значок в трее Fly/KDE с процентами лимитов; по клику открывается панель, как на Mac: простой вид или расширенный (темп, столбики за 7 дней, календарь за 35 дней, деньги) | `python3-pyqt5` из репозитория ОС |

Предыдущие версии порта проверены на Astra Linux SE 1.8.5 (Python 3.11, PyQt5 5.15, KDE Plasma / Fly).
Для кандидата 0.4.5 CI, QA и живая проверка ALSE ещё не подтверждены. Код совместим
с Python 3.7, который стоит в Astra 1.7. Никаких `pip install` не требуется.

## Linux 0.4.5 / Linux 0.4.5 candidate

**Кандидат до CI, QA и выпуска координатором / Candidate pending CI, QA and coordinator release.** Инструкции 0.4.5 сверены с исходниками freeze3; исполнение и пакет здесь не проверялись. Instructions were checked against freeze3 source, without runtime or package acceptance. Latest остаётся macOS 3.2.7; Linux DEB должен выйти как `linux-v0.4.5`, не Latest.

**RU:** Войдите в нужный CLI и включите подписки в Настройках. В простом или расширенном виде нажмите небольшую иконку обновления рядом с Настройками в прежней шапке. Статус запроса и время данных компактно показаны внутри карточки сервиса; подробности — в подсказке. Выбор **15м / 30м / 1ч / 4ч** включает фиксированный режим (4ч сохраняются как 14400 секунд); старые 1/5 минут заменяются на 30 минут. **«А»** включает Auto: подсвечиваются «А» и фактические интервалы только включённых сервисов, при разных интервалах — оба сегмента. При выключенных подписках интервалы не подсвечены; «А» может оставаться выбранной в Auto. Отдельной частоты и строки «Темп по снимку от…» нет; прогнозы и нужные сообщения о проблемах сохраняются.

**EN:** Sign in through the required CLI and enable subscriptions in Settings. In Simple or Advanced view, use the small refresh icon beside Settings in the existing header. Each provider card contains compact request status and data time; its tooltip provides details. Select **15m / 30m / 1h / 4h** for fixed polling (4h is saved as 14400 seconds); old 1/5-minute settings migrate to 30 minutes. **A** selects Auto, highlighting A and the actual intervals of enabled providers; different intervals highlight both segments. With both subscriptions off, no interval is highlighted; A may remain selected in Auto. There is no standalone frequency or “Pace from snapshot at…” annotation; forecasts and necessary warnings remain.

**Ручное обновление — контракт кандидата:** обходит локальное расписание Auto/фиксированного опроса и паузу после ошибки, сохраняя выбранный режим. Защита 30 секунд и один одновременный запрос действуют отдельно для каждого сервиса; результаты появляются независимо, повтор доступен только для проблемного сервиса. Реальный Retry-After соблюдается. Неизменившийся живой ответ — успех; fallback сохраняет исходное время данных. Проблема входа показывает следующий шаг для нужного CLI без автоматического входа и запросов разрешений; механизм macOS Keychain permit на Linux не переносится.

**Manual refresh — candidate contract:** bypass the local Auto/fixed schedule and error backoff while keeping the selected mode. Each provider has a 30-second guard and at most one request in flight; results appear independently, with retry for just the failed provider. Respect actual Retry-After deadlines. An unchanged live answer is a success; fallback keeps the old data timestamp. Show guidance for the affected CLI without automatic login or permission prompts; Linux does not use macOS Keychain permits. [RU/EN notes and post-release installation](../docs/linux-compact-refresh-release.md).

## Установка 0.4.5 после выпуска

Следующие шаги предназначены для будущего опубликованного пакета; кандидат ещё ожидает CI/QA и выпуска координатором.

### Пакет .deb (рекомендуется)

1. После выпуска скачайте `claude-codex-limits_0.4.5_all.deb` из `linux-v0.4.5`
   в [списке релизов](https://github.com/ArrivaRUS/claude-codex-limits/releases).
2. Откройте файл двойным щелчком и нажмите «Установить» (нужен пароль администратора) или
   поставьте из терминала:
   ```sh
   sudo apt install ./claude-codex-limits_0.4.5_all.deb
   ```
   Зависимости `python3-pyqt5` и `python3-dbus` apt возьмёт из репозитория ОС.
3. Запустите **Claude Codex Limits** из меню приложений. При первом запуске значок включает себе
   автозапуск (выключается в настройках).

Что ставит пакет:

- программу → `/usr/share/claude-codex-limits/`, команды `ccl-sync` и `claude-codex-limits` → `/usr/bin/`,
  ярлык в меню и иконку;
- таймер синхронизации `ccl-sync.timer` (раз в 10 минут) для всех пользователей — со следующего
  входа в систему, а до того синхронизирует сам значок. У тех, кто не входил в GitHub, таймер сразу
  завершается и ничего не создаёт в их домашнем каталоге.

Удаление: `sudo apt remove claude-codex-limits`. Настройки, индекс и вход в GitHub в домашнем
каталоге остаются. Если раньше ставили через `install.sh`, удалите ту копию: `sh linux/uninstall.sh`
(данные останутся), иначе она будет перекрывать пакет.

С включённой ЗПС (замкнутой программной средой) пакет не проверялся.

### В домашний каталог, без sudo

```sh
git clone https://github.com/ArrivaRUS/claude-codex-limits.git
cd claude-codex-limits
sh linux/install.sh
```

Так всё ставится только в домашний каталог:

- программы → `~/.local/share/claude-codex-limits/`, команды `ccl-sync` и `claude-codex-limits` → `~/.local/bin/`
- таймер синхронизации раз в 10 минут → `~/.config/systemd/user/ccl-sync.{service,timer}`; если нет `systemctl --user`, используется cron
- автозапуск значка → `~/.config/autostart/claude-codex-limits.desktop`, ярлык в меню приложений
- ключи установщика: `--no-autostart`, `--no-timer`; удаление: `sh linux/uninstall.sh [--purge]`

Скрипты всегда запускаются через системный интерпретатор (`/usr/bin/python3 <скрипт>`). Это
вариант, который работает при включённом контроле интерпретаторов Astra, и бит исполнения на
самих скриптах не нужен.

## Синхронизация с Mac

```sh
ccl-sync login     # один раз: печатает код и ссылку github.com/login/device, ждёт подтверждения
ccl-sync push      # один проход: индекс логов → файл этой машины в gist → чтение остальных
ccl-sync status    # кто вошёл, gist, какие машины в нём и когда обновлялись
ccl-sync dump      # расход по дням и моделям из локальных логов (--days N, --product, --merged, --json)
ccl-sync logout    # удалить токен с этой машины (gist остаётся)
ccl-sync update    # обновиться: из main, а для пакета — скачать новый .deb (--check — только проверить)
```

Войти можно и из значка: **Настройки → Синхронизация через GitHub → Войти через GitHub**.
Новый явный вход запрашивает `gist offline_access`: доступ к gist и возможность
автоматического продления, если GitHub выдаёт refresh. Токен хранится в хранилище секретов
рабочего стола (KWallet или GNOME Keyring через `org.freedesktop.secrets`), либо в выбранном при явном входе файле `~/.config/claude-codex-limits/github-token` с правами `0600`. Токен нигде не печатается.

Если синхронизация не работает, это видно. `ccl-sync status` печатает «Последняя отправка: HH:mm ·
чтение: HH:mm» и последнюю ошибку со временем. В настройках значка показано то же самое. Если вход
выполнен, а удачной синхронизации не было больше 30 минут, в «Истории и деньгах» появляется
оранжевая строка «Синхронизация стоит с HH:mm: <причина>». Один ответ 401 не доказывает отзыв: доступ сначала пытается восстановить
автоматическое продление, затем окончательный отказ проверяется цепочкой 401 на gist
и двумя 401 на `GET /user` с паузой около 4 секунд. Временная ошибка сети или
хранилища сохраняет последнюю надёжную выдачу и повторяется с backoff; при rate limit
учитывается пауза GitHub. Чтение выбранного Secret Service не переключается на файл
из-за timeout. Хранилище «недоступно» отличается от действительно отсутствующего ключа.

В версии 0.4.3 действующий legacy-вход не требует перевхода. Новая
выдача сохраняется целиком с refresh и сроками, если они пришли от GitHub. Обслуживание
входа и обмен выполняются независимо от простого/расширенного вида и Auto опроса
лимитов. После сна/restart следующий фоновый цикл заново проверяет срок; во сне
продлевать вход не требуется. Неопределённый ответ продления сначала восстанавливается
по сохранённой паре, а бюджет дополнительной issuer попытки ограничен. Если новый
результат утрачен без возможности восстановления, refresh истёк, ключ потерян или
GitHub отозвал доступ, нужен один явный `ccl-sync login` или вход в Настройках.

`ccl-sync logout` отключает только эту машину и очищает локальные access/refresh;
gist и вход на других машинах остаются. Если хранилище не подтвердило удаление,
приложение честно сообщает незавершённую очистку: повторите выход после разблокировки.
Запоздалый refresh/login не должен восстановить отключённую сессию.

Linux 0.4.3 опубликован; код, DEB и публичный скачанный пакет проверены: [notes](../docs/release-notes-linux-0.4.3.md).
Синтетические месяцы не подтверждают шесть месяцев реального использования или
живую проверку ALSE/KWallet/Fly.

Что уходит в gist: только суммы токенов по продукту, дню и модели за последние 45 дней. Промпты,
пути, названия проектов и id сессий туда не попадают. На Mac эти данные появляются в расширенном
виде: в «Истории и деньгах» ПК складываются, а в настройках синхронизации видна эта машина.

## Выбор подписок и интервал обновления

Инструкция для **кандидата 0.4.5**, ожидающего CI/QA и выпуска. В настройках есть блок **«Собирать и показывать»** с отдельными
переключателями Claude Code и Codex. Чтобы оставить только Codex, выключите Claude Code.
Выбор сохраняется на этом компьютере и действует для простого и расширенного вида, трея,
уведомлений и фонового сборщика `ccl-sync`. Можно выключить обе подписки; настройки останутся
доступны через значок в трее.

Отключённая подписка перестаёт опрашиваться и индексироваться, исключается из новых отправок
синхронизации и скрывается из графиков, включая данные других компьютеров. Сохранённая локальная
история остаётся; при повторном включении журналы дочитываются с прежней позиции.

Внизу панели выберите **15 минут / 30 минут / 1 час / 4 часа** для фиксированного опроса; по умолчанию — 30 минут. Поддерживаемый выбор сохраняется, в том числе 4ч (14400 секунд); старые 1/5 минут заменяются на 30 минут. Таймер синхронизации расхода работает отдельно, раз в 10 минут.

**«А» (Auto)** включает адаптивный режим: при активном расходе опрос идёт раз в 15 минут, при низком — постепенно раз в 30 минут, час и 4 часа. Расписания сервисов отдельные и сохраняются после перезапуска. В обоих видах одновременно подсвечены «А» и фактические интервалы включённых сервисов; разные интервалы дают два активных сегмента. Подсказки связывают их с сервисами. При обеих выключенных подписках интервалы не подсвечены; «А» может оставаться выбранной. Отдельной частоты справа от «А» нет. Нажатие любого интервала выключает Auto; по умолчанию Auto выключен.

Активный расход — рост любого сопоставимого лимита со скоростью ≥1 процентного пункта за 15 минут.
Дополнительно раз в 2 минуты проверяются локальные журналы без запросов к Anthropic/OpenAI:
три разных события с ненулевым расходом за последние 15 минут возвращают быстрый опрос.
Сбросы лимита и старые записи не считаются активностью. Если работа идёт только на другом
компьютере, она обнаружится при следующем запросе, максимум через 4 часа в спокойном режиме.

Само открытие панели не запрашивает новые лимиты. Нажмите небольшую иконку **«Обновить сейчас»** рядом с Настройками: запрос обходит локальное расписание и паузу после ошибки, сохраняя режим. У каждого сервиса — защита 30 секунд от начала попытки, один запрос одновременно и соблюдение реального Retry-After. Результаты появляются независимо; после ожидания **«Повторить»** в проблемной карточке запрашивает только этот сервис. Неизменившийся живой ответ — успех; при fallback остаётся исходное время данных. Подсказка различает время данных и следующую автопопытку. Строки «Темп по снимку от…» нет, прогнозы сохраняются.

**«Восстановить доступ»** показывает шаги для нужного CLI: запустите `claude` и выполните `/login` либо выполните `codex login`. При ошибке чтения/сохранения проверьте пользователя CLI, доступность файла входа и место на диске. Затем нажмите «Повторить». Страница не запускает вход или запрос разрешений автоматически; macOS Keychain permit на Linux не используется.

## Уведомления и обновления

- Когда лимит исчерпан (100%) или окно сбросилось, приходит уведомление на рабочий стол. Его
  можно выключить: **Настройки → Уведомления и звуки**. Там же включаются звуки, как на Mac.
- Раз в 6 часов значок проверяет, не вышла ли новая версия. Если вышла, на шестерёнке появляется
  оранжевая точка, а в настройках и в меню значка — кнопка обновления.
  - **Пакет .deb** смотрит релизы `linux-v…` на GitHub. Кнопка «Скачать и установить» кладёт
    новый пакет в «Загрузки» и открывает установщик пакетов; после установки значок
    перезапускается сам.
  - **Установка через `install.sh`** смотрит версию в `main` (`APP_VERSION` в
    `linux/ccl/__init__.py`). Кнопка «Обновить» скачивает `main`, берёт из архива только `linux/`
    и `Resources/`, запускает его `install.sh` с теми же настройками автозапуска и таймера и
    перезапускает значок.
  - Копию, запущенную из git-репозитория, обновление не трогает — её обновляют через `git pull`.

## Устаревшие данные и вход

Возраст показаний или ошибка сети не доказывают истечение входа. При устаревших
данных карточка сохраняет последние проценты, приостанавливает расчёт темпа и
предлагает обновить данные. Если время чтения неизвестно — «Нет свежих данных ·
темп не считаем», без подстановки текущего времени. Подсказка входа Claude
появляется только в карточке Claude при состоянии «вход не выполнен» или «вход
истёк»; ошибка чтения credentials не означает истёкший вход. Карточка Codex
с устаревшими данными не предлагает `claude login`.

## Откуда берутся цифры

- **Лимиты в процентах** общие для всей учётки и приходят с серверов:
  - Claude: `GET api.anthropic.com/api/oauth/usage` с токеном из `~/.claude/.credentials.json`,
    то есть с входом **Claude Code CLI**;
  - Codex: `GET chatgpt.com/backend-api/wham/usage` с токеном из `~/.codex/auth.json`, а при
    ошибке — из последних rollout-файлов.

  Токен Claude обновляется, только когда до его истечения осталось меньше 2 минут. Новая пара
  атомарно записывается обратно, остальные поля файла сохраняются. Если сам CLI успел обновить
  токен раньше, записанное им не перезаписывается. Отказанный refresh-токен повторно не
  отправляется.
- **Расход по дням и моделям** берётся из логов этой машины: `~/.claude/projects/**.jsonl`
  (включая `subagents/agent-*.jsonl`, каждое сообщение считается один раз в день) и
  `~/.codex/sessions/**/rollout-*.jsonl` (события `token_count`). Индекс инкрементальный: при
  каждом проходе дочитываются только новые полные строки. Первый проход по ~1,8 ГБ логов занимает
  около 4 секунд, последующие — доли секунды.

> Claude Code внутри **настольного приложения Claude** использует собственный вход и не
> обновляет `~/.claude/.credentials.json`. Если CLI не установлен или вход в нём устарел,
> карточка Claude покажет «Вход устарел → Как починить?» с командами установки и входа.
> Codex и синхронизация расхода работают и без этого входа.

## Где что лежит

| путь | что |

## Разработка

```sh
python3 -m unittest discover -s linux/tests -v
python3 linux/ccl-sync dump --days 3      # запуск из репозитория без установки
python3 linux/claude-codex-limits
```

Пакет и релиз:

```sh
sh linux/packaging/build-deb.sh     # → dist/claude-codex-limits_<версия>_all.deb (нужен только dpkg-deb)
sh linux/packaging/release.sh       # на свежем main: релиз linux-v<версия> с этим .deb
```

`release.sh` создаёт релиз с `--latest=false`. Пометка Latest должна оставаться у Mac-релиза:
обновление на Mac и `get.sh` берут `releases/latest` и ищут там `.dmg`. Linux-релиз с пометкой
Latest сломает и то, и другое.

Модули: `ccl/usage.py` — индекс логов, цены и деньги; `ccl/sync.py` — протокол gist и Device Flow; `ccl/auth.py` — владелец выдачи и продления;
`ccl/vault.py` — хранилище секретов или файл; `ccl/update.py` — обновления; `ccl/limits.py` — лимиты, кэш, история, темп;
`ccl/gui/` — трей и панель (порт `drawPanel` и `drawAdvanced`).
