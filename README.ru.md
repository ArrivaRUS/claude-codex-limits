# Claude Codex Limits

[English](README.md) · **Русский**

<p align="center">
  <img src="docs/banner.png?v=314" alt="Claude Codex Limits — лимиты в строке меню macOS" width="820">

Маленькое приложение для строки меню macOS, которое показывает, сколько у вас осталось
лимитов **Claude Code** и **Codex** — одним взглядом, прямо в верхнем трее.

В каждой строке — `сессия% / неделя%` (скользящее 5‑часовое окно и 7‑дневное окно),
слева иконка продукта; какие именно два числа показывать — решаете вы.
По клику на иконку в трее открывается подробная панель.

## macOS 3.2.6: ручное обновление (кандидат в релиз)

3.2.6 — кандидат в релиз, идёт финальная пакетная QA. Выпуск и установка ещё
не выполнены: сейчас на Mac установлена 3.2.5; Linux остаётся на 0.4.4.
Ниже описано поведение кандидата.

Включите хотя бы одну подписку в Настройках и войдите в соответствующий CLI.
Откройте простой или расширенный вид панели и нажмите **«Обновить сейчас»**
в шапке. Кнопка запрашивает свежие лимиты включённых сервисов, не дожидаясь
интервала Auto или фиксированного расписания, в том числе после локальной
паузы из-за ошибки сети. Выбранный режим опроса сохраняется. Открытие панели
в Auto по-прежнему соблюдает расписание.

- Каждый сервис показывает **«Обновляем…»**, затем свой результат. Один сервис
  может закончить раньше другого. Успешный ответ с прежними процентами тоже
  означает успешное обновление.
- **«Данные»** — время показаний, **«Следующая автопопытка»** — расписание.
  При сбое остаются прежние цифры с исходным временем; старый снимок не становится
  свежим от нажатия кнопки. Неизвестное время обозначается `—`.
- Если сбой только у одного сервиса, после указанного ожидания нажмите
  **«Повторить»** рядом с ним. Повторные нажатия не запускают второй уже идущий
  запрос. **Локальная защита на 30 секунд** отсчитывается от начала попытки,
  действует отдельно от Auto и не является ограничением сервера.
- **«Сервис разрешит повтор через…»** означает, что сервер передал срок повтора
  (`Retry-After`). Ручное обновление соблюдает его; автоматическая попытка
  допускается по истечении этого срока. Неизвестный серверный срок не выдумывается.
- Обычное **«Обновить сейчас»** и фоновые попытки выполняются без системных окон
  разрешений. Только если чтению записи Claude нужно разрешение, после указанного
  ожидания появляется **«Разрешить доступ к Связке ключей»**. Это одна попытка
  чтения до 15 секунд, в которой возможно системное окно. **«Отменить»** прекращает
  попытку; для новой нужен новый явный запрос. Разрешение чтения не разрешает запись
  обновлённых данных входа и не меняет права доступа автоматически.
- При **«Не удалось сохранить обновлённый вход»** откройте **«Восстановить доступ»**,
  разблокируйте Связку ключей и нажмите «Обновить сейчас» для повтора сохранения. Разрешение чтения
  не означает успешного сохранения. Ошибка чтения или записи сама по себе не требует
  повторного входа. Если сохранение всё ещё не удаётся, новый `claude login` —
  дополнительный способ восстановления. При фактической проблеме входа выполните инструкцию CLI:
  `claude login` для Claude или `codex login` для Codex, затем обновите данные.

Обновление лимитов отделено от **«Повторить доступ к Связке ключей»** в настройках
синхронизации GitHub. [Черновик RU/EN заметок и оставшиеся проверки](docs/manual-refresh-release.md).

## macOS 3.2.5: фоновый доступ GitHub без окон Связки ключей

Фоновые обращения GitHub к Связке ключей выполняются с запретом системных окон,
включая запуск, пробуждение и очистку данных входа. Если нужно разрешение,
синхронизация ждёт, сохраняя данные входа. Linux остаётся на 0.4.4.

На Mac с версией 3.2.5 откройте Настройки → Синхронизация через GitHub и
нажмите **«Повторить доступ к Связке ключей»**, если хранилищу нужно разрешение.
Попытка ограничена по времени; системное окно может появиться в рамках этого
действия. Разрешайте доступ, только если узнаёте приложение и запрошенную запись
GitHub. Отмена или отказ завершает попытку; новый интерактивный повтор требует
нового нажатия. Войдите заново только если приложение просит новый вход.

Существующей записи может понадобиться ручное разрешение: меняется помощник,
который обращается к ней. **«Разрешать всегда»** действует для конкретной записи
и запрашивающего приложения, а не всех записей сервиса. Не разрешайте доступ
всем приложениям и не выгружайте токен в обычный текстовый файл. Точная причина
повторных окон у пользователя не установлена. Прежняя пауза **600 секунд** лишь
откладывала повторы; ожидание или перезапуск не разблокировали Связку ключей.
Повторы по расписанию сохраняют запрет системных окон.

Это изменение не добавляет нотаризацию и не меняет Gatekeeper. Отсутствующая
диагностика темпа Codex остаётся отдельным долгом; её исправление в 3.2.5 не заявлено.
См. [RU/EN заметки к выпуску и ограничения проверки](docs/keychain-quiet-release.md).

## Возможности

- **Два продукта — один взгляд.** Claude Code (рыжий) над Codex, проценты `сессия / неделя`.
- **Живые данные.** Оба читают лимиты с тех же бэкендов, что и их CLI. Когда свежие показания недоступны, карточка отмечает сохранённые данные как устаревшие.
- **Честно об устаревших данных.** Возраст показаний или ошибка сети не доказывают, что вход истёк. Снимок с известным временем допустим по возрасту до 4 часов включительно; один сбой запроса его не обесценивает. Темп считается на момент чтения, окна проверяются независимо. После истечения срока карточка сохраняет проценты и предлагает обновить данные. Если время чтения неизвестно, показывает «Нет свежих данных · темп не считаем». Инструкция входа Claude появляется только у Claude при состоянии «вход не выполнен» или «вход истёк»; устаревшая карточка Codex не показывает `claude login`.
- **Лимиты по моделям.** У модели со своим 7‑дневным лимитом (например, Fable) появляется собственная пилюля с процентом и строка со временем сброса. Обычно именно в него упираешься первым: он может быть на 100%, когда общий недельный ещё не исчерпан. Название модели берётся с бэкенда, так что новые появятся сами.
- **Расширенный режим.** Второй вид панели для тех, кто хочет лимитами *управлять*, а не только поглядывать. У каждого окна — строка темпа: где по линейному плану вы должны быть сейчас, на сколько пунктов опережаете, средняя скорость расхода и вердикт словами — «Хватит до сброса (прогноз 53%)» или «Кончится в 09:37, за 2 ч 13 мин до сброса». Ниже — расход за 7 дней столбиками стопкой по моделям, календарь за 35 дней и деньги: сколько стоит день по подписке и сколько те же токены стоили бы по ценам API. Отдельно по Claude Code и Codex. Настройки → «Вид панели».
- **Несколько компьютеров — одна учётка.** Войдите в GitHub в настройках, и каждый компьютер с утилитой будет складывать свой локальный расход в один секретный gist, а каждая копия — показывать общие столбики, календарь и деньги. Передаётся только сводка токенов по дням и моделям — без промптов, путей и названий проектов. Есть версия для Astra Linux — см. [Linux](#linux-astra-linux) ([протокол](docs/sync-protocol.md)).
- **Строка меню — на ваш выбор.** Выбираете, какое число стоит слева от слэша, а какое справа (5‑часовой, недельный или лимит модели), и в каком порядке; правое можно погасить и оставить одно число. Настройки → «В строке меню». Трей меняется сразу по нажатию.
- **Сбросы Codex.** Если накоплены сбросы лимита («банкинг сбросов»), на карточке Codex показывается маленький бейдж ⟳ с их количеством.
- **Цветовые предупреждения.** Цифры и кольца желтеют при ≥50% и краснеют при ≥80% лимита.
- **Подробная панель.** Клик по иконке — кольцевые гейджи, точные проценты, время сброса.
- **Клик по карточке** открывает страницу с лимитами в браузере.
- **Выбор подписок.** Настройки → «Собирать и показывать»: независимые переключатели Claude Code и Codex в простом и расширенном виде. Можно оставить только Codex или выключить оба. Для выключенного продукта останавливаются опрос API и индексация журналов, скрываются данные в трее, панели и истории, а его статистика исключается из новых отправок синхронизации с этого Mac. Сохранённая локальная история остаётся; при включении журналы дочитываются. Выбор сохраняется на этом компьютере.
- **Один или оба продукта** — если настроен только Claude Code или только Codex, трей и панель сворачиваются в одну строку / одну карточку.
- **Открытие панели обновляет лимиты** при фиксированном интервале; в режиме «А» соблюдается расписание.
- **Интервал обновления** — 15 минут, 30 минут или 1 час на выбор. По умолчанию — 30 минут; сохранённый выбор 15 минут или 1 час остаётся. Прежние настройки на 1/5 минут автоматически заменяются на 30 минут.
- **Адаптивный опрос («А»)** — включается кнопкой рядом с интервалами. Активный расход возвращает опрос к 15 минутам; при низком расходе пауза последовательно растёт до 30 минут, 1 часа и 4 часов. Расписание отдельное для Claude Code и Codex и сохраняется после перезапуска. При включённом Auto кнопка «А» выделена сине-фиолетовым градиентом, а текущая частота видна рядом в простом и расширенном видах. Для одной подписки или одинаковых интервалов показано одно время; для разных — отдельно по продуктам, например `Claude 15м · Codex 4ч`. Если обе подписки выключены, написано «нет подписок». Время последнего обновления в Auto доступно в подсказке на «А». По умолчанию авто выключено, остаются 30 минут.
- **Звуковые уведомления (опционально)** — весёлый перезвон при *сбросе* 5ч/недельного лимита и грустный тон при достижении **любого** лимита, включая модельный; звук выбирается отдельно для каждого события в настройках (⚙).
- **Автоматические обновления** — проверка новых релизов в фоне (при запуске + каждые 6 ч); когда появляется новее, в трее и на шестерёнке ⚙ загорается точка. В настройках **Что нового** показывает релиз-ноуты за все пропущенные версии, а **Скачать** → живой прогресс-бар → **Установить и перезапустить** сразу ставит последнюю. Без Sparkle и нотаризации.
- **Два языка (RU / EN)** — переключение всего интерфейса между русским и английским в настройках; релиз-ноуты тоже на выбранном языке. По умолчанию русский.
- **Светлая и тёмная** строка меню, чётко на retina.
- **Автозапуск при входе** — тумблер прямо в настройках; без иконки в Dock, без сторонних зависимостей.

## Как это работает

**Claude Code** (лимиты подписки). Приложение читает ваши существующие OAuth‑креденшелы
Claude Code из связки ключей macOS (`Claude Code-credentials`), обновляя access‑токен
ровно так же, как это делает CLI Claude Code, и запрашивает эндпоинт использования
Anthropic `GET /api/oauth/usage`. **Это не тратит вашу квоту** — берутся только
`five_hour.utilization` (сессия), `seven_day.utilization` (неделя) и структурированный
массив `limits[]` для недельных лимитов по моделям (`kind: "weekly_scoped"`, название из
`scope.model.display_name`). Старые поля по моделям (`seven_day_opus` и подобные) теперь
возвращают `null`, так что `limits[]` — единственный источник для них.

**Codex** (OpenAI). Приложение тянет **живые** данные с того же бэкенда, что и Codex CLI —
`GET /backend-api/wham/usage` — при допущенном правилами опроса обновлении
(см. Auto и ручное обновление выше), авторизуясь локальным токеном из `~/.codex/auth.json` (с авто‑обновлением через
токен‑эндпоинт OpenAI, когда он протух). `primary_window` — 5‑часовое окно, `secondary_window`
— 7‑дневное. Если живой запрос не прошёл, берётся самый свежий локальный журнал сессий
(`~/.codex/sessions/**/rollout-*.jsonl`).

**Расширенный режим.** Для темпа хватает текущего показания и времени сброса окна. Столбики,
календарь и деньги берутся из локальных журналов самих CLI — `~/.claude/projects/*/*.jsonl` и
`~/.codex/sessions/**/rollout-*.jsonl`, — где записаны токены и модель каждого хода. Поэтому проценты
и темп — это вся учётка, с какого бы компьютера вы ни работали, а столбики, календарь и деньги — то,
что запускалось на этом Mac, плюс на других компьютерах, вошедших в тот же GitHub, если включить синхронизацию. Приложение индексирует журналы инкрементально (читает только байты, дописанные с прошлого раза) и оценивает
токены по встроенной таблице публичных цен API по моделям; неизвестные модели не оцениваются
вовсе, а не угадываются. Цена подписки, где можно, выводится из плана (у Claude — из tier
лимитов) и редактируется в настройках; названия планов Codex на публичные цены не ложатся,
поэтому там оценка, пока вы не зададите свою. Ещё приложение хранит собственные замеры
использования (35 дней, в `~/.claude-limits-monitor/`), чтобы темп со временем опирался на
ваш недавний расход, а не только на среднее по окну.

Никуда ничего не отправляется, кроме авторизованных запросов использования в Anthropic и OpenAI
(от вашего имени). Никакой телеметрии и сторонних сервисов. Рантайм‑кэш и резервная копия
креденшелов хранятся в `~/.claude-limits-monitor/`.

## Установка

### 1. Установка одной командой (рекомендуется)

```bash
curl -fsSL https://raw.githubusercontent.com/ArrivaRUS/claude-codex-limits/main/get.sh | bash
```

Скачивает последний релиз и ставит его прямо в **Applications** **без диалогов
Gatekeeper** — приложение, скачанное через `curl`, не получает карантин-атрибут,
поэтому macOS не помечает его как «повреждённое» или «от неизвестного разработчика».
Автозапуск при входе остаётся **выключен**, пока вы не включите его в настройках.

### 2. Из .dmg

1. Скачайте `ClaudeCodexLimits-3.2.2.dmg` из релиза [macOS 3.2.2](../../releases/tag/v3.2.2).
2. Откройте и перетащите **Claude Codex Limits** в **Applications**.
3. Запустите. Сборка не нотаризована, поэтому на **macOS Sequoia / Tahoe** первый
   запуск блокируется. Сделайте один раз:
   - В окне блокировки нажмите **«Отмена»** (⚠️ **не** «Переместить в Корзину»).
   - Откройте **Системные настройки → Конфиденциальность и безопасность**,
     прокрутите вниз, нажмите **«Всё равно открыть»** и подтвердите.
   - **Если кнопки «Всё равно открыть» нет**, снимите карантин-атрибут в Терминале
     и затем откройте приложение обычным способом:
     ```bash
     xattr -dr com.apple.quarantine "/Applications/Claude Codex Limits.app"
     ```
4. Иконка появится справа в строке меню.

### Из исходников

```bash
git clone https://github.com/ArrivaRUS/claude-codex-limits.git
cd claude-codex-limits
./install.sh        # собрать, поставить в /Applications, включить автозапуск, запустить
```

Требуется: macOS 13+, командные инструменты Xcode (`swiftc`). Ставить пакеты не нужно.

### Linux (Astra Linux)

Предыдущие версии Linux-порта проверены на Astra Linux SE 1.8 (KDE / Fly). Правка UI 0.4.2 пока не проверена на живой ALSE; Linux CI использует Ubuntu 22.04. Порт даёт значок в трее с теми же
процентами, панель с простым и расширенным видом и синхронизацию расхода с Mac через тот же gist.

1. Скачайте `claude-codex-limits_0.4.2_all.deb` из релиза [Linux 0.4.2](../../releases/tag/linux-v0.4.2).
2. Откройте файл двойным щелчком и нажмите «Установить» или поставьте из терминала:
   ```bash
   sudo apt install ./claude-codex-limits_0.4.2_all.deb
   ```

## Использование

- **Левый клик** по иконке в трее → открыть/закрыть панель.
- **Клик по карточке** → открыть страницу лимитов продукта в браузере.
- **Кнопка обновления** → запросить новые лимиты. В черновике macOS 3.2.6 она подписана **«Обновить сейчас»** в шапке; инструкция выше.
- **Кнопки интервала** (внизу) → 15 мин / 30 мин / 1 час / **А** (авто).
- **Кнопка выключения** (внизу справа) → выход.
- **Правый клик** по иконке → запасное меню (Обновить / Автозапуск / Выйти).

### Как работает автоматический опрос

Активным считается рост любого сопоставимого лимита не менее чем на 1 процентный пункт за 15 минут (скорость рассчитывается за время между замерами). Первый ответ задаёт исходные значения, сброс окна лимита не считается расходом. Новые локальные записи с ненулевым расходом токенов проверяются раз в 2 минуты без обращения к API: три разных события за последние 15 минут также возвращают опрос к 15 минутам.

В macOS 3.2.5 и Linux 0.4.4 открытие панели в режиме «А» не ускоряет опрос; ручное обновление допускается не раньше чем через 15 минут после предыдущего ответа. Ошибки и ответы из кэша увеличивают паузу, которую локальная активность и ручное обновление не сокращают. Принятый сценарий macOS 3.2.6 выше отделяет ручной запрос от этого локального расписания; поведение Linux сохраняется. Активность только на другом компьютере обнаруживается при следующем запросе — в спокойном режиме ожидание может достигать 4 часов. Синхронизация истории имеет собственное расписание.
