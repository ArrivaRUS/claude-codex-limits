# 009 — «Merge в main = выкладка Linux» — неверно для пакета

**Дата:** 2026-09-30 · **Где:** процесс выкладки Linux (0.3.0+, пакет .deb)

## Что случилось

Мак-сторона смержила Linux 0.3.2 (фикс тихого отзыва синка) в `main` и записала в HEARTBEAT
и журнал решений «Linux сам обновляется из `main`, merge — это выкладка». С 0.3.0 Linux
ставится пакетом .deb в `/usr`, а трей в пакете смотрит только GitHub-релизы `linux-v<версия>`
с `*_all.deb`. Релиза не было — ни ThinkPad, ни другие установки 0.3.x обновления не увидели
бы. Заметила Linux-сторона при сборке; релиз `linux-v0.3.2` опубликован по «опубликуй» человека.

## Почему не поймали

Правило про выкладку жило в памяти Мак-стороны со времён установки через `install.sh`
(обновление из `main`, до 0.3.0). Переход на .deb описан в `linux/README.md` и
`linux/packaging/release.sh`, но в HEARTBEAT и журнал решений не попал.

## Правило на будущее

1. Выкладка Linux = `sh linux/packaging/release.sh [заметки]` на актуальном `main`: тег
   `linux-v<APP_VERSION>`, файл .deb, **всегда не Latest** (Latest читают обновлятор Мака и `get.sh`).
   Merge в `main` сам по себе ничего не выкладывает (кроме устаревших установок через `install.sh`).
2. Linux-правки проверять на живой машине Linux-стороной: там есть PyQt5, dpkg, KDE и KWallet —
   GUI- и .deb-тесты, которые на Маке пропускаются, идут только там.
3. Смена способа доставки = запись в HEARTBEAT и журнал решений в том же PR.
