# 008 — Латали окна гонки по одному вместо корня

**Дата:** 2026-09-30 · **Где:** Linux `vault._timed`/`store()` (запись токена в Secret Service)

## Что случилось

Класс «KeyboardInterrupt посреди записи токена оставляет неотслеживаемую копию» всплывал
четыре раза подряд, каждый раз новым окном: ожидание `done.wait` (цикл 3) → `t.start()` вне
`try` (F-1) → ветка таймаута `_timed` → двойное прерывание в обработчике. Каждое ревью
находило следующее микросекундное окно; каждый фикс закрывал ровно одно. Ушло три лишних
цикла правка→ревью, пока человек не утвердил корневой фикс: SIGINT откладывается на время
критической секции (`_sigint_deferred`).

## Почему

Фикс брифовался по формулировке находки («перенеси строку в try»), а не по классу дефекта.
Асинхронное исключение (сигнал) может прийти между любыми двумя байткодами — точечные
перестановки строк этот класс не закрывают в принципе.

## Правило на будущее

- Находка вида «асинхронное событие (сигнал, kill, таймаут, отмена) в окне X» → в бриф
  разработчику писать **класс**: «перечисли все окна, где это событие ломает инвариант, и
  закрой механизмом (маскирование/отсрочка, журнал-до-действия, идемпотентная очистка)».
- Второе окно того же класса = стоп, корневой фикс, не третий точечный (правило «один баг
  >2 раз = долг процесса» срабатывает уже на втором).
