# 023 — AppKit-хвост с утра не прогонялся, а компилятором работал владелец: три лишних прогона

**Дата:** 2026-11-01 · **Веха:** C5 (C5-24…26) · **Тесты:** C5-26, Auth hints (AppKit-хвост)

## Что случилось

Код C5-24…26 прошёл ревью (`38f2182`). Проверки C5-25/26 рисуют окно и поэтому живут в AppKit-хвосте `--subscriptions-selftest`. Удалённые руки на маке AppKit запустить не могут (нет экрана, exit 134), так что Юрка сразу отдал владельцу команду «сборка + все тесты + превью». Получилось три прогона вместо одного:

1. **owner-build-6: сборка упала на компиляции.** Sol удалил переменную теста `two`, а одно её использование оставил (`RemoteLimitsC3BSelfTests.swift:457`). На Linux компилятора Swift нет. Удалённые руки компилируют до шага подписи и поймали бы ошибку за ~10 минут без владельца, но этот шаг Юрка пропустил.
2. **owner-selftest-7: хвост остановился на первом FAIL.** Проверка C5-26 ждала полных имён в строке «в активный день» и для EN. По-английски строка шире 308 pt, и программа правильно сжимает её до «Claude / Codex» по §5 макета. Неверным было ожидание теста, а не код.
3. **owner-selftest-8: следующий FAIL дальше по хвосту.** Проверка Auth hints ждала, что у Codex без сессии строки «Сессия» нет. С `6eebca7` (утро 01.11, решение владельца) эта строка есть всегда. AppKit-хвост с тех пор ни разу не доходил до конца: удалённые руки падают на AppKit, а владелец ставил сборки без тестов.

После ревизии хвоста Sol'ом (`c0e66f5`) хвост копит FAIL и печатает итог. owner-selftest-9: 9917 OK / 0 FAIL, хвост 7885/0.

## Правило на будущее

1. **Владелец — не компилятор.** Если клон владельца уже стоит на нужной ревизии, перед командой сборки владельцу сначала идёт прогон удалённых рук в строгом режиме: он компилирует и гоняет всё до AppKit. Если владельцу всё равно нужен `git pull` (удалённые руки ветку не тянут), команда владельца сразу делает «pull → сборка → все тесты → установка только при 0 FAIL». Сбой компиляции тогда стоит один повтор той же команды, столько же, сколько отдельный pull (уточнено 2026-11-01, сборка 10).
2. **Тесты не обрываются на первом FAIL.** AppKit-хвост копит сбои и печатает `AppKit tail: N OK / M FAIL` (`c0e66f5`). Новые наборы проверок пишутся так же: ранний выход только там, где дальше будет краш.
3. **Изменение видимого правила затрагивает и AppKit-хвост.** Ревизия старых ожиданий (урок 019) включает `check`/`authCheck` хвоста. Если хвост не прогонялся с момента изменения, первый прогон владельца — тесты без установки.
4. **Ожидание текста в тесте выводится из правила, а не из одного языка.** Сжатие строки по ширине проверяется измерением: «полные имена, если влезают в 308 pt». Нельзя переносить на EN то, что верно для RU.
