# 025 — 3.4.0: Связка ключей молчала после перезагрузки; 3.4.1 дошёл до зелёного за 5 прогонов у владельца

**Дата:** 2026-11-02 … 03 · **Версии:** 3.4.0 → 3.4.1

## Что случилось
1. **Баг в выпущенном 3.4.0.** Пункт Связки создавал helper через `SecItemAdd` — в списке разделов (partition list) только его cdhash, без `apple-tool:`. Чтение через `/usr/bin/security` поднимало окно разрешения, а оно пряталось под панелью уровня `.popUpMenu` → через 15 с «Связка ключей не ответила». Живой гейт C5 шёл на старом, уже разрешённом пункте и без повторного входа — свежесозданный пункт ни разу не читали.
2. **3.4.1 — пять сборок у владельца до зелёного:** не компилировалось (`check: check` при `@autoclosure`); C3-38 был прибит к версии 3.4.0; проверка формата `dump-keychain -a` (разделы печатаются не так, как ждали); тест ждал ненулевой код `security -i`, а он 0 при сбое подкоманды (сам код это уже учитывал — комментарий рядом!); C5-14 поймал настоящий баг UI (reason-only состояние без текста ошибки в Settings).
3. Урок 023 («перед командой владельцу — прогон удалённых рук: компиляция + всё до AppKit») не выполнен: компилятором снова работал владелец.
4. Мелочь у Юрки: циклы `until ! pgrep -f "<шаблон>"` находили сами себя и не завершались; `pkill` по такому шаблону убил собственный shell.

## Правило на будущее
- **Связка ключей:** у любого пункта, который читает внешний бинарь (`/usr/bin/security`), создатель должен быть тем же бинарём или партиция `apple-tool:` должна быть доказана. Живой гейт Связки = **выход → вход (свежий пункт) → перезагрузка → чтение без окон**, а не только «старый пункт читается».
- **Окно системы под нашей панелью** (`.popUpMenu`) = для пользователя «зависло». Любое действие, способное поднять системный диалог, опускает панель (`GitHubKeychainPanelSuspension`).
- **Перед каждой командой сборки владельцу — удалённые руки на MacBook** (`skills/remote-hands`): компиляция + selftest до AppKit. Владелец — не компилятор (повтор урока 023 → «долг процесса»: в бриф developer-а на Swift вписывать «последний шаг — прогон удалённых рук, без него не сдавать»).
- **Тест внешнего бинаря — сначала записать факт его поведения** (диагностическая строка `K341 TEMP …`), потом ставить жёсткое ожидание. Не утверждать формат вывода системной утилиты, который не видели.
- **Версию приложения в тестах не прибивать к литералу** — сравнивать с `APP_VERSION` из одного места, проверять только формат/монотонность.
- **Состояние «только причина, без текста»** (reason-only) — тест на всех экранах, где показывается ошибка: одно состояние — один источник текста (`settingsErrorText`).
- **Ожидание процесса** — по PID или файлу-флагу, не `pgrep -f` по шаблону, содержащемуся в собственной командной строке; `pkill -f` не применять вовсе.
