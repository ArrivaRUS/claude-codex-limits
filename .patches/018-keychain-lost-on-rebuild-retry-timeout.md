# 018 — Новая сборка теряет доступ к Связке ключей; кнопка повтора сдаётся по таймауту

**Дата:** 2026-10-31 · **Веха:** C4, живая проверка 3.3.0 на маке

## Что случилось

Сборка `f93f9c3` прошла все селфтесты (C4 730/730, C3 813/813) и 198 PNG, но в живом приложении издатель мака не отправил ни одного файла почти сутки. Причина — ad-hoc подпись новой сборки: macOS не отдаёт ей пункт Связки ключей со входом GitHub, сохранённый прошлой сборкой («Связке ключей нужно разрешение»). Кнопка «Повторить доступ к Связке ключей» открывает окно с паролем, но чтение уходит по таймауту раньше, чем владелец успевает ввести пароль («Связка ключей не ответила»). Помог только «Выйти» → вход заново. Ровно то же было 29.10 на 3.2.7 — записано как «переходное», а не как дефект.

Селфтесты этого не ловят: под удалёнными руками Связки ключей нет, транспорт и хранилище — инъекции.

## Правило на будущее

1. **Живой прогон macOS-сборки начинается с проверки синка в настройках** («Последняя отправка» свежая, GitHub зелёный) и gist со стороны VPS (`ccl-sync status` → строка мака с новой версией) — до любых других проверок. Нет свежей отправки за 10 мин — сразу скриншот блока GitHub, не ждать.
2. **Повтор, требующий действия человека в системном окне, не ограничивается коротким дедлайном** фонового чтения: ждём ответа окна (или минуты), а таймаут фонового чтения — отдельный.
3. **Одно и то же «переходное» состояние второй раз = дефект**, заводить в журнал решений с вехой исправления (здесь D4 → C6: стабильная подпись или ACL пункта).


## C5 / 3.3.1 — исправление кода, 2026-10-31

Повтор чтения по кнопке получил общий deadline 120 с для завершения helper и чтения вывода, фон сохраняет 15 с. Кнопка и высота строки зависят только от locked/unreachable/timeout. Модельные инжектированные проверки — C5-03/04, зарегистрированы до AppKit; системный prompt и новая сборка ещё требуют живого Mac-прогона. Стабильная подпись/ACL остаются отдельной заботой C6.

Уточнение владельца31.10: D4 read continuity перенесён вC5. V2 читает через уже
доверенный `/usr/bin/security`, не меняя ACL; legacy сохраняет прежний native путь.
Ошибка может сохраняться в lastError после очистки authReason: действие и текст
нужно выводить из единого состояния, включая восстановленные ошибки. C5-13/14,
actual Settings hits и живой гейт без logout/login — docs/c5-github-keychain-audit.md.
Стабильная подпись сборок остаётся C6.

После принятого security-review `48ac3ad` (S1–S5): tool44 подтверждается нативным
attributes-only запросом; background получает native quiet preflight/unlocked
check.120с нужно проверять через owner retry, а не только runner: quiet-first
может оборвать ручную попытку за15с. Трубу ограничивать при чтении, не после;
retry hit/height должны отсутствовать в awaitingCode, где обработчик отказывает.

Решение владельца31.10: постоянная clone-local подпись также перенесена вC5.
`.signing/` нельзя чистить между сборками; build log должен показывать stable
и тот же leaf prefix. Явный identifier+leaf DR, не cdhash; fallback ad-hoc не
считать доказательством сохранения разрешений. Mac smoke обязателен после
однократного Allow Always для прежних пунктов. См. build section project-guide.
