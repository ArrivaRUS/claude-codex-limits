# 013 — Cooldown не запрещает системные диалоги

2026-10-07. Пользователь повторно сообщил об окнах GitHub Credential V2 после3.2.4 и подтвердил «Разрешать всегда».

Ошибка подхода: общий600s cooldown проверял частоту ошибок хранилища, а не право фонового вызова показывать UI. Успешный Allow очищает gate; restart его теряет; другие generations имеют свои ACL. Pure счётчики retry не доказывают отсутствие системного окна.

Правило: фоновые native Keychain вызовы должны явно запрещать UI внутри исполняющего helper. Ошибка установки запрета прекращает RPC. Интерактивный допуск принадлежит явному действию, ограничен операцией, отзывается при отмене и не достаётся cleanup. Недоступность не означает missing/revoked. Новая helper identity может потребовать ручного разрешения старой записи; нельзя автоматически расширять ACL.

Проверки: параметр реального boundary, отказ установки policy → ноль RPC, quiet/manual×read/stage/readback/delete/legacy, restart, cancelled login, uncertain writer. Нативные ACL/popup без отдельной изолированной среды не считаются проверенными по mocks/compile. Независимое ревьюsnapshot1 дополнительно нашло cancel race и зависание recovery после killed probe; исправления приняты наsnapshot3, включая дополнительную гонку заимствования permit новой попытки. Документы: docs/keychain-no-background-prompts.md и docs/test-plan-keychain-quiet.md.
